Can Multiple OpenCL Kernels Share a Pipe?

This article examines whether multiple OpenCL kernels can concurrently read from and write to the same pipe object. Introduced in OpenCL 2.0, pipes provide a first-in, first-out (FIFO) data structure for efficient kernel communication. While OpenCL allows one producer kernel and one consumer kernel to execute concurrently on the same pipe, the specification strictly limits this model to a single-producer, single-consumer design, preventing multiple distinct kernels from writing to or reading from the same pipe simultaneously.

The Single-Producer, Single-Consumer Model

In OpenCL, pipes are designed to facilitate streaming architectures where data passes directly between execution stages without round-tripping through global memory. A pipe can connect two concurrently executing kernels on the same device:

  • One writer kernel declared with the write_only pipe qualifier.
  • One reader kernel declared with the read_only pipe qualifier.

When launched into an out-of-order command queue or across separate queues targeting the same device, these two kernels can execute at the same time. The producer pushes packets to the pipe, and the consumer pulls packets from it concurrently.

Restrictions on Multiple Distinct Kernels

OpenCL does not support multiple writer kernels (M-to-1) or multiple reader kernels (1-to-N, M-to-N) accessing the same pipe concurrently.

  1. No Multiple Producer Kernels: You cannot have two separate kernel instances concurrently writing to the same pipe. Attempting to bind multiple active writer kernels to a single pipe leads to undefined behavior or driver-level command queue serialization.
  2. No Multiple Consumer Kernels: Similarly, you cannot divide the workload across multiple distinct consumer kernels reading from a single pipe at the same time. Only one consumer kernel can own the read interface during execution.

If an application requires data from multiple distinct kernels to be merged, or requires data to be distributed across multiple downstream kernels, the application must route data through global memory buffers or serialize the pipeline stages.

Concurrency Inside a Single Kernel

Although multiple kernels cannot concurrently write to or read from the same pipe, thousands of work-items within the same kernel can. OpenCL provides built-in reservation functions to safely manage concurrent access among work-items and work-groups:

  • reserve_read_pipe and reserve_write_pipe allow individual work-items to atomically reserve space for transactions.
  • work_group_reserve_read_pipe and work_group_reserve_write_pipe coordinate reservations collectively across an entire work-group.
  • commit_read_pipe and commit_write_pipe finalize the transactions, ensuring consistency across the hardware threads.

These built-in functions ensure that race conditions do not corrupt data when hundreds of work-items within the designated producer or consumer kernel perform concurrent read and write operations.

Conclusion

Multiple OpenCL kernels cannot simultaneously write to or simultaneously read from the same pipe. The OpenCL pipe architecture strictly supports concurrency between exactly one producer kernel and one consumer kernel. High-throughput parallel reads and writes are only possible among the work-items and work-groups operating inside those individual, dedicated kernel instances.
