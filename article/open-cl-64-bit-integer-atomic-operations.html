OpenCL 64-Bit Integer Atomic Operations

In OpenCL, atomic read-modify-write (RMW) operations on 64-bit integers allow multiple work-items to safely update shared 64-bit data in global or local memory without race conditions. While 32-bit atomic operations are mandatory across most standard OpenCL implementations, 64-bit integer atomics are historically treated as optional features that depend on specific hardware capabilities, API versions, and extension support. OpenCL handles these operations through dedicated built-in functions, explicit memory orderings, and hardware-level atomic instructions or compare-and-swap emulation loops.

Standard Evolution and Extension Support

In OpenCL 1.x, atomic operations on 64-bit integers (long and ulong) are not part of the core specification. Instead, they require explicit extension support declared in the kernel:

  • cl_khr_int64_base_atomics: Enables fundamental 64-bit operations, including atom_add, atom_sub, atom_xchg, atom_inc, atom_dec, and atom_cmpxchg.
  • cl_khr_int64_extended_atomics: Enables bitwise and comparative operations, including atom_min, atom_max, atom_and, atom_or, and atom_xor.

To use these in OpenCL 1.x kernels, the extension must be enabled using the pragma directive:

#pragma OPENCL EXTENSION cl_khr_int64_base_atomics : enable
#pragma OPENCL EXTENSION cl_khr_int64_extended_atomics : enable

Starting with OpenCL 2.0, atomic operations were overhauled to align with the C11 memory model. OpenCL 2.0 introduced the atomic_long and atomic_ulong types, along with unified atomic functions (e.g., atomic_fetch_add, atomic_fetch_or). In OpenCL 2.x and OpenCL 3.0, 64-bit atomics remain optional and are guarded by the feature test macros __opencl_c_int64_base_atomics and __opencl_c_int64_extended_atomics.

Memory Consistency and Memory Scopes

In modern OpenCL (2.0 and later), 64-bit atomic RMW operations take memory order and memory scope arguments to define visibility across the compute hierarchy:

  • Memory Order: Dictates synchronization constraints. Options include memory_order_relaxed, memory_order_acquire, memory_order_release, memory_order_acq_rel, and memory_order_seq_cst.
  • Memory Scope: Determines which work-items observe the synchronization. Options include:
    • memory_scope_work_group: Synchronization applies only within the local work-group.
    • memory_scope_device: Synchronization applies across all work-items on the device.
    • memory_scope_all_svm_devices: Synchronization applies across both the host CPU and OpenCL devices sharing virtual memory.

A typical OpenCL 2.0+ RMW operation using explicit scopes looks like:

atomic_fetch_add_explicit(
    (volatile __global atomic_long *)ptr, 
    value, 
    memory_order_relaxed, 
    memory_scope_device
);

Hardware Execution Mechanics

OpenCL runtimes and device drivers translate 64-bit atomic functions into machine-level instructions using two primary approaches:

  1. Native Hardware Atomics: Modern GPUs and discrete accelerators with native 64-bit execution units directly execute 64-bit atomic memory instructions (such as native atomic addition or exchange at the memory controller or L2 cache level). This ensures minimal overhead and non-blocking execution.
  2. Compare-And-Swap (CAS) Loops: If the target hardware does not have dedicated functional units for complex 64-bit operations (like atomic_fetch_max or bitwise operations), the OpenCL compiler synthesizes the operation using an atomic compare-and-exchange loop (atomic_compare_exchange_weak or atomic_compare_exchange_strong). The loop continuously reads the memory address, computes the operation locally, and attempts to write the result back until the CAS instruction succeeds.

Memory Alignment Requirements

For any 64-bit atomic RMW operation to execute safely, the target memory address must be naturally aligned to an 8-byte boundary. Accessing unaligned 64-bit pointers in atomic operations results in undefined behavior in OpenCL, typically causing kernel crashes, memory faults, or non-atomic split transactions that lead to silent data corruption.
