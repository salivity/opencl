How to Configure OpenCL Device-Side Queues

This article explains how to configure and allocate device-side command queues in OpenCL host applications to enable nested parallelism and device-enqueued kernels. Starting with OpenCL 2.0, device-side queues allow kernels to enqueue work directly on the compute device without host intervention. Below is a direct walkthrough of how host applications query device support, allocate the required queue objects with specific property flags, and bind them to kernels.

Checking Device Capabilities

Before allocating a device-side command queue, the host application must confirm that the target device supports OpenCL 2.0 or higher and has device-side queue capabilities. Use clGetDeviceInfo with the following parameters:

  • CL_DEVICE_QUEUE_ON_DEVICE_PROPERTIES: Returns a bitfield indicating the supported properties for device-side queues. A conforming device must at least support CL_QUEUE_ON_DEVICE and CL_QUEUE_OUT_OF_ORDER_EXEC_MODE_ENABLE.
  • CL_DEVICE_MAX_ON_DEVICE_QUEUES: Returns the maximum number of device queues that can be active simultaneously.
  • CL_DEVICE_QUEUE_ON_DEVICE_MAX_SIZE: Returns the maximum size, in bytes, allowed for a device-side command queue.
  • CL_DEVICE_QUEUE_ON_DEVICE_PREFERRED_SIZE: Returns the recommended queue size in bytes for optimal performance.

Allocating the Device Queue on the Host

In OpenCL 2.0 and later, command queues are allocated using the clCreateCommandQueueWithProperties function. Device queues require specific key-value attribute pairs passed through a cl_queue_properties array:

  1. CL_QUEUE_PROPERTIES: Must include both CL_QUEUE_ON_DEVICE and CL_QUEUE_OUT_OF_ORDER_EXEC_MODE_ENABLE. Device queues must always operate in out-of-order execution mode.
  2. CL_QUEUE_SIZE: Specifies the queue capacity in bytes. This value must not exceed the CL_DEVICE_QUEUE_ON_DEVICE_MAX_SIZE queried from the device.
  3. CL_QUEUE_ON_DEVICE_DEFAULT (Optional): If passed with CL_TRUE, this designates the created queue as the default device queue for the device, eliminating the need to pass a queue parameter directly into kernel arguments.

An allocation setup typically looks like this:

cl_queue_properties queue_props[] = {
    CL_QUEUE_PROPERTIES, 
    CL_QUEUE_ON_DEVICE | CL_QUEUE_OUT_OF_ORDER_EXEC_MODE_ENABLE | CL_QUEUE_ON_DEVICE_DEFAULT,
    CL_QUEUE_SIZE, preferred_queue_size,
    0
};

cl_int err;
cl_command_queue device_queue = clCreateCommandQueueWithProperties(
    context, 
    device_id, 
    queue_props, 
    &err
);

Passing the Queue to Kernels

Once created, the host application connects the queue to the OpenCL execution environment in one of two ways:

  • As a Kernel Argument: If a queue is not designated as the default, the host passes the queue handle to the kernel via clSetKernelArg. Inside the OpenCL C kernel code, the parameter must be declared with the queue_t data type.
  • As the Default Queue: If the CL_QUEUE_ON_DEVICE_DEFAULT flag was set during creation, the kernel can implicitly obtain the queue reference by calling the built-in OpenCL C function get_default_queue() without needing an explicit argument set from the host.

Memory and Lifetime Management

Device-side command queues reside in device memory and consume on-device resources. When the queue is no longer needed by the host or any pending child kernels, it must be released from the host using clReleaseCommandQueue. The OpenCL runtime ensures that memory allocated for the queue is not freed until all parent and child kernels that access the queue have completed execution.
