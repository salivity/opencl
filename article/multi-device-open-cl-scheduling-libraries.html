Multi-Device OpenCL Scheduling Libraries

Managing heterogeneous hardware systems comprising CPUs, integrated GPUs, discrete GPUs, and accelerators requires robust orchestration to prevent resource starvation and minimize latency. This article explores the primary open-source runtime systems and orchestration libraries that automate multi-device scheduling and memory management for OpenCL backends, detailing how they handle task distribution, data transfers, and load balancing across diverse computing units.

The Complexity of Manual OpenCL Multi-Device Management

OpenCL provides standard abstractions for heterogeneous computing, but native multi-device utilization requires developers to manually construct distinct command queues, track data dependencies, balance compute loads, and synchronize memory buffers across multiple devices. Without an orchestration layer, scaling an application to multiple OpenCL devices introduces significant boilerplate code and increases the risk of pipeline stalls or race conditions. Automated orchestration runtimes abstract these concerns using task-based directed acyclic graphs (DAGs) and dynamic scheduling engines.

Top Open-Source Multi-Device OpenCL Orchestration Runtimes

1. StarPU

StarPU is a mature task-based runtime system developed by Inria designed specifically to coordinate heterogeneous architectures featuring CPUs, GPUs, and accelerators.

  • Scheduling Mechanisms: StarPU models execution as a task graph (DAG). Tasks represent kernels with defined memory footprints and dependencies. It features built-in dynamic schedulers, including Heterogeneous Earliest Finish Time (HEFT), minimum execution time estimation, and work-stealing heuristics.
  • OpenCL Support: StarPU maintains native support for OpenCL backends alongside CUDA and standard CPU threads. It automatically provisions OpenCL command queues across detected devices and handles asynchronous kernel launches.
  • Memory Management: It uses an internal software-managed cache coherency protocol (MSI/MOSI-like) that handles data transfers across discrete device memories, replicating data only when necessary and evicting cold buffers.

2. OmpSs-2

Developed by the Barcelona Supercomputing Center (BSC), OmpSs-2 extends the OpenMP model to heterogeneous environments, using compiler directives and an asynchronous runtime to automate execution across heterogeneous hardware.

  • Scheduling Mechanisms: The runtime analyzes task dependencies dynamically at runtime via annotated directives (#pragma oss task). It schedules ready tasks onto the most suitable compute target based on device availability, historical execution times, and data affinity.
  • OpenCL Support: OmpSs-2 features an OpenCL target plugin that translates annotated code into asynchronous OpenCL tasks. The runtime manages device contexts, kernel compilation, and queue dispatch without manual intervention.
  • Memory Management: Memory movement between host memory and individual OpenCL device spaces is automatically coordinated using directional task pragmas (in, out, inout).

3. SkePU

SkePU is a high-level skeleton programming framework that abstracts parallel patterns (such as Map, Reduce, Scan, and MapReduce) for multi-core and multi-GPU architectures.

  • Scheduling Mechanisms: Instead of low-level task graphs, SkePU operates at the pattern level. It can dynamically decompose arrays and distribute execution across multiple OpenCL-capable devices.
  • OpenCL Support: It features both OpenCL and CUDA backends. When compiled with multi-device support, SkePU partitions container data across multiple queues and executes kernels concurrently across all available devices.
  • Tuning and Optimizations: SkePU includes an integrated machine-learning and heuristic auto-tuning mechanism that predicts whether a single GPU, multiple GPUs, or the host CPU will deliver the best throughput for a given input size.

4. HPX (High Performance Computing in C++)

HPX is an open-source, general-purpose C++ parallel programming library maintained by the STE||AR Group. It implements the C++ standard concurrency extensions and scales from multi-core chips to distributed supercomputers.

  • Scheduling Mechanisms: HPX replaces traditional threading models with an asynchronous execution graph driven by futures and dataflow components.
  • OpenCL Integration: Through community integrations such as HPXCL, HPX exposes OpenCL devices as asynchronous executors. This architecture allows developers to chain OpenCL kernel executions with CPU tasks via standard hpx::future constructs, enabling dynamic task migration and overlap of compute with I/O.
  • Work Distribution: Work is distributed across devices using an advanced work-stealing algorithm that prevents device starvation by moving deferred tasks between scheduler queues.

Key Evaluation Criteria for Selection

Selecting an orchestration framework for multi-device OpenCL pipelines depends on system requirements:

  • Directive-Driven vs. API-Driven: Teams seeking to minimize refactoring of existing C/C++ code typically select OmpSs-2 for its pragma-driven syntax. For maximum programmatic control over task graphs and hardware mapping, StarPU provides the most configurable C-level runtime APIs.
  • Pattern Abstraction: Workloads dominated by standard data-parallel operations (such as array transformations or reductions) benefit from SkePU, which eliminates direct kernel programming while managing multi-device splits internally.
  • C++ Concurrency Integration: Projects built on modern standard C++ patterns benefit most from HPX, as it bridges OpenCL execution queues directly into modern standard library asynchronous constructs.
