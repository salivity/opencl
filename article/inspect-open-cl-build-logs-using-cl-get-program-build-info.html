Inspect OpenCL Build Logs Using clGetProgramBuildInfo

When compiling OpenCL kernels at runtime using clBuildProgram, syntax errors and hardware-incompatible code cause the build to fail silently without outputting diagnostics to standard streams. This article demonstrates how to intercept compilation errors by querying the OpenCL runtime with clGetProgramBuildInfo. By following a two-step query pattern, developers can dynamically allocate the necessary buffer, extract the compiler's diagnostic output, and print detailed error logs directly to the console.

Checking for Build Errors

When clBuildProgram fails, it returns an error code—most commonly CL_BUILD_PROGRAM_FAILURE. Instead of terminating immediately, you should capture this return code and initiate a query against the program and target device to fetch the diagnostic log.

cl_int err = clBuildProgram(program, 1, &device_id, options, NULL, NULL);
if (err != CL_SUCCESS) {
    // Proceed to retrieve the build log
}

Retrieving the Build Log

Extracting the log with clGetProgramBuildInfo requires two calls: the first determines the log size in bytes, and the second copies the log data into an allocated character buffer.

1. Query the Log Size

Call clGetProgramBuildInfo with CL_PROGRAM_BUILD_LOG as the param_name. Pass NULL for the param_value parameter and provide a pointer to a size_t variable to receive the size of the log.

size_t log_size = 0;
clGetProgramBuildInfo(
    program, 
    device_id, 
    CL_PROGRAM_BUILD_LOG, 
    0, 
    NULL, 
    &log_size
);

2. Allocate Buffer and Fetch the Log

Allocate a buffer of size log_size. Then, invoke clGetProgramBuildInfo again, passing the allocated buffer to param_value and log_size to param_value_size.

char *build_log = (char *)malloc(log_size);
clGetProgramBuildInfo(
    program, 
    device_id, 
    CL_PROGRAM_BUILD_LOG, 
    log_size, 
    build_log, 
    NULL
);

Complete Implementation Example

Below is a self-contained helper function that prints the compilation log whenever clBuildProgram encounters an error:

#include <CL/cl.h>
#include <stdio.h>
#include <stdlib.h>

void check_and_print_build_log(cl_program program, cl_device_id device) {
    size_t log_size = 0;
    
    // First query: Retrieve buffer size needed for the log
    clGetProgramBuildInfo(program, device, CL_PROGRAM_BUILD_LOG, 0, NULL, &log_size);

    if (log_size > 1) { // A log size of 1 usually means an empty null-terminated string
        char *log = (char *)malloc(log_size);
        if (log != NULL) {
            // Second query: Populate the buffer with the compiler output
            clGetProgramBuildInfo(program, device, CL_PROGRAM_BUILD_LOG, log_size, log, NULL);
            fprintf(stderr, "=== OpenCL Build Log ===\n%s\n", log);
            free(log);
        }
    }
}

Key Considerations

  • Multi-Device Contexts: If your OpenCL context targets multiple devices, clBuildProgram compiles code for each device independently. You must loop over each cl_device_id and call clGetProgramBuildInfo separately to identify which specific device failed and view its respective log.
  • Non-Fatal Warnings: Even if clBuildProgram returns CL_SUCCESS, the build log may still contain compiler warnings or optimization notes. You can execute this query pattern after successful builds to diagnose potential performance bottlenecks.
