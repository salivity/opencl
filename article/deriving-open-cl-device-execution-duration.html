Deriving OpenCL Device Execution Duration

In OpenCL, accurately measuring the execution time of commands on an OpenCL device involves querying hardware timestamps recorded during command processing. By enabling profiling on the target command queue and capturing the associated event, developers can retrieve the CL_PROFILING_COMMAND_START and CL_PROFILING_COMMAND_END values to compute the total elapsed duration. This article outlines the mechanism for capturing these timestamps, explains the mathematical derivation of execution time, and provides a concise implementation pattern.

Enabling Queue Profiling

To record timestamps, the target command queue must be created with profiling enabled. You must pass the CL_QUEUE_PROFILING_ENABLE flag within the queue properties to clCreateCommandQueueWithProperties (or clCreateCommandQueue in OpenCL 1.x/2.0):

cl_queue_properties properties[] = {
    CL_QUEUE_PROPERTIES, CL_QUEUE_PROFILING_ENABLE,
    0
};
cl_command_queue queue = clCreateCommandQueueWithProperties(context, device, properties, &err);

If profiling is not explicitly enabled on the queue, querying profiling information will return a CL_PROFILING_INFO_NOT_AVAILABLE error.

Capturing the Command Event

When enqueuing an operation—such as a kernel execution with clEnqueueNDRangeKernel or a memory transfer with clEnqueueReadBuffer—pass a pointer to a cl_event variable as the final parameter. This event tracks the lifecycle of that specific operation.

cl_event event;
clEnqueueNDRangeKernel(queue, kernel, work_dim, NULL, global_work_size, local_work_size, 0, NULL, &event);

Before reading profiling timestamps, the host must ensure the command has finished executing by calling clWaitForEvents or clFinish.

Retrieving Start and End Timestamps

The OpenCL runtime records hardware counter values for different execution phases. The relevant queries are:

  • CL_PROFILING_COMMAND_START: The timestamp (in nanoseconds) indicating when the command began actual execution on the device.
  • CL_PROFILING_COMMAND_END: The timestamp (in nanoseconds) indicating when the command completed execution on the device.

Both values are queried using clGetEventProfilingInfo and stored as 64-bit unsigned integers (cl_ulong):

cl_ulong time_start = 0;
cl_ulong time_end = 0;

clGetEventProfilingInfo(event, CL_PROFILING_COMMAND_START, sizeof(cl_ulong), &time_start, NULL);
clGetEventProfilingInfo(event, CL_PROFILING_COMMAND_END, sizeof(cl_ulong), &time_end, NULL);

Deriving the Execution Duration

The timestamps represent counter points on a monotonic device clock calibrated in nanoseconds. The device execution duration is calculated by subtracting the start time from the end time:

\[\text{Execution Duration (ns)} = \text{CL\_PROFILING\_COMMAND\_END} - \text{CL\_PROFILING\_COMMAND\_START}\]

To convert nanoseconds into standard units for reporting:

  • Milliseconds (ms): \(\text{Duration (ns)} \times 10^{-6}\) (or divide by 1,000,000.0)
  • Seconds (s): \(\text{Duration (ns)} \times 10^{-9}\) (or divide by 1,000,000,000.0)
cl_ulong duration_ns = time_end - time_start;
double duration_ms = (double)duration_ns / 1000000.0;

This derived value reflects strictly the time spent executing on the hardware compute units, excluding queue submission latency, dependency wait times, and host-device synchronization overhead. Always release the captured event via clReleaseEvent(event) after profiling is complete.
