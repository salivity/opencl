OpenCL 3D Texture Filtering & Trilinear Interpolation

This article covers how OpenCL samples volumetric data using texture filtering and trilinear interpolation on 3D image objects. It explores the sampler configurations required to enable hardware-accelerated filtering, breaks down the mathematical mechanics of trilinear interpolation across eight neighboring voxels, and explains how dedicated graphics hardware optimizes volumetric sampling compared to standard buffer reads.

OpenCL 3D Images and Sampler Configuration

In OpenCL, volumetric data is represented using the image3d_t data type. Unlike raw linear memory buffers, OpenCL image objects are bound to dedicated texture hardware on supported GPUs. Reading from a 3D image inside a kernel requires an OpenCL sampler object (sampler_t) and built-in functions such as read_imagef.

To enable hardware-accelerated filtering, the sampler must be configured with specific flags:

  • Coordinate Normalization: CLK_NORMALIZED_COORDS_TRUE or CLK_NORMALIZED_COORDS_FALSE. Normalized coordinates map spatial dimensions to the range \([0.0, 1.0]\), whereas unnormalized coordinates map directly to voxel indices \([0, \text{dim} - 1]\).
  • Addressing Mode: Specifies edge handling (e.g., CLK_ADDRESS_CLAMP_TO_EDGE, CLK_ADDRESS_REPEAT, or CLK_ADDRESS_CLAMP).
  • Filter Mode: Specifies how values between discrete voxels are determined. Selecting CLK_FILTER_NEAREST yields point sampling (nearest-neighbor), while CLK_FILTER_LINEAR enables linear interpolation.

When querying an image3d_t using CLK_FILTER_LINEAR, the hardware automatically initiates trilinear interpolation across the three-dimensional grid.

The Mechanics of Trilinear Interpolation

Trilinear interpolation estimates the value of an arbitrary point within a 3D grid by calculating a weighted average of the eight nearest surrounding voxels. The process extends 1D linear interpolation across three orthogonal axes (\(X\), \(Y\), and \(Z\)).

1. Determining Surrounding Voxels and Fractional Offsets

Given a continuous sampling coordinate \((u, v, w)\) mapped to voxel space:

  1. The hardware identifies the bounding indices of the sampling cube: \[x_0 = \lfloor u - 0.5 \rfloor, \quad x_1 = x_0 + 1\] \[y_0 = \lfloor v - 0.5 \rfloor, \quad y_1 = y_0 + 1\] \[z_0 = \lfloor w - 0.5 \rfloor, \quad z_1 = z_0 + 1\]
  2. It calculates the fractional distances (interpolation weights) from the lower coordinate: \[f_x = (u - 0.5) - x_0\] \[f_y = (v - 0.5) - y_0\] \[f_z = (w - 0.5) - z_0\] Each fractional factor \(f_x, f_y, f_z\) falls strictly within the range \([0.0, 1.0]\).

2. Multi-Pass Interpolation Sequence

Trilinear interpolation evaluates the target value using seven successive linear interpolations:

  • Step 1: Four interpolations along the X-axis. The hardware blends the eight corner values pair-wise along the \(X\) direction, reducing the eight corners to four intermediate values on the \(Y\)-\(Z\) plane: \[C_{00} = V(x_0, y_0, z_0)(1 - f_x) + V(x_1, y_0, z_0)f_x\] \[C_{10} = V(x_0, y_1, z_0)(1 - f_x) + V(x_1, y_1, z_0)f_x\] \[C_{01} = V(x_0, y_0, z_1)(1 - f_x) + V(x_1, y_0, z_1)f_x\] \[C_{11} = V(x_0, y_1, z_1)(1 - f_x) + V(x_1, y_1, z_1)f_x\]

  • Step 2: Two interpolations along the Y-axis. The four intermediate points are blended along the \(Y\) direction, reducing them to two points along the \(Z\) axis: \[C_0 = C_{00}(1 - f_y) + C_{10}f_y\] \[C_1 = C_{01}(1 - f_y) + C_{11}f_y\]

  • Step 3: One final interpolation along the Z-axis. The remaining two points are blended along the \(Z\) direction to compute the final sampled value: \[\text{Result} = C_0(1 - f_z) + C_1 f_z\]

The final value can also be expressed directly as a single weighted summation:

\[\text{Result} = \sum_{i=0}^{1} \sum_{j=0}^{1} \sum_{k=0}^{1} V(x_i, y_j, z_k) \cdot \left| (1 - i) - f_x \right| \cdot \left| (1 - j) - f_y \right| \cdot \left| (1 - k) - f_z \right|\]

Boundary Handling and Clamping

When sampling coordinates fall near the boundaries of the 3D volume, the OpenCL addressing mode dictates how neighboring voxels outside the volume boundary are selected:

  • CLK_ADDRESS_CLAMP_TO_EDGE: Coordinates outside the range \([0, \text{dimension}-1]\) are clamped to the border voxel index. The interpolation will blend between valid edge voxels and duplicate values of that edge.
  • CLK_ADDRESS_CLAMP: Coordinates outside the valid image range return a predefined border color (transparent black by default: \((0.0, 0.0, 0.0, 0.0)\) or \((0.0, 0.0, 0.0, 1.0)\) depending on image channel order).
  • CLK_ADDRESS_REPEAT: Coordinates wrap around via modulo arithmetic, causing interpolation to blend opposing faces of the 3D volume across borders.

Hardware Acceleration vs. Manual Buffer Math

Performing trilinear interpolation manually on a standard 1D buffer (__global float*) requires:

  1. Executing boundary calculations for all three dimensions.
  2. Computing eight distinct 1D offsets: \(\text{index} = z \cdot (\text{width} \cdot \text{height}) + y \cdot \text{width} + x\).
  3. Issuing eight separate, high-latency memory fetches.
  4. Executing seven floating-point fused multiply-add operations manually in the ALU.

When using image3d_t and read_imagef with CLK_FILTER_LINEAR, this entire workflow is offloaded to the GPU's Texture Mapping Units (TMUs). The TMU utilizes specialized cache hierarchies optimized for 3D spatial locality (often Morton/Z-order curve layouts) and contains fixed-function blending circuits that calculate the trilinear result in minimal hardware clock cycles, bypassing general ALU instructions entirely.
