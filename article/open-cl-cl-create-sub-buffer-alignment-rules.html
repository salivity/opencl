OpenCL clCreateSubBuffer Alignment Rules

Creating sub-buffers in OpenCL using clCreateSubBuffer allows applications to partition an existing buffer without copying data. However, defining the sub-buffer region requires strict adherence to hardware-specific memory alignment rules for the offset. Failing to align the region offset properly results in runtime failures, primarily the CL_MISALIGNED_SUB_BUFFER_OFFSET error. This article outlines the exact alignment criteria, calculation requirements, and multi-device considerations necessary to safely create sub-buffers.

The Origin Alignment Requirement

When creating a sub-buffer using CL_BUFFER_CREATE_TYPE_REGION, you must supply a cl_buffer_region structure specifying an origin (byte offset) and a size. The OpenCL specification mandates that the origin field must be an even multiple of the device's base address alignment.

This alignment constraint does not apply to the size parameter—only origin must meet the strict alignment boundary, though origin + size cannot exceed the parent buffer's total capacity.

Querying CL_DEVICE_MEM_BASE_ADDR_ALIGN

To find the required alignment for a specific device, query clGetDeviceInfo using the flag CL_DEVICE_MEM_BASE_ADDR_ALIGN.

A critical detail often overlooked is that CL_DEVICE_MEM_BASE_ADDR_ALIGN returns the value in bits, not bytes. Because the origin offset in cl_buffer_region is measured in bytes, you must convert the device property before calculating your offset:

cl_uint align_bits;
clGetDeviceInfo(device, CL_DEVICE_MEM_BASE_ADDR_ALIGN, sizeof(align_bits), &align_bits, NULL);
size_t align_bytes = align_bits / 8;

Your origin value must satisfy the following condition:

(origin % align_bytes) == 0

Common values for align_bits are 1024, 2048, or 4096, which translate to alignment requirements of 128, 256, or 512 bytes, respectively.

Handling Contexts with Multiple Devices

If the OpenCL context associated with the parent buffer contains multiple devices, the origin must satisfy the alignment requirements for all devices in that context.

If different devices report different base address alignments, the origin must be aligned to the least common multiple of all devices' alignment constraints. In practice, because alignment values are powers of two, the offset must be an integer multiple of the largest CL_DEVICE_MEM_BASE_ADDR_ALIGN value among all devices in the context.

Error Conditions

If the alignment rule is violated:

  • The call to clCreateSubBuffer fails and returns CL_MISALIGNED_SUB_BUFFER_OFFSET.
  • If origin and size describe an out-of-bounds region relative to the parent buffer, or if pointers are invalid, the API returns CL_INVALID_VALUE.

Data Type Alignment in Device Kernels

Beyond the API-enforced CL_DEVICE_MEM_BASE_ADDR_ALIGN constraint, the chosen origin should also maintain proper natural alignment for the data types processed inside the OpenCL C kernel (such as float4 or int8). While CL_DEVICE_MEM_BASE_ADDR_ALIGN is almost always much larger than the alignment requirement of standard vector types, ensuring custom offsets align with both API requirements and kernel-side data structures prevents undefined memory access behavior on strict hardware architectures.
