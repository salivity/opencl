How to Inspect OpenCL Assembly and ISA Output

Inspecting the low-level assembly or Instruction Set Architecture (ISA) generated by an OpenCL compiler is an essential step for fine-tuning kernel performance, diagnosing register pressure, and understanding hardware resource utilization. This article provides a concise technical guide detailing how developers can extract and analyze intermediate representations (IR) and target-specific machine code across different hardware platforms using standard OpenCL API calls, vendor-specific build options, environment variables, and offline compilation tools.

Querying Binaries via the OpenCL API

The most portable way to retrieve compiled output directly within your application is through the OpenCL Runtime API. Once a program is built with clBuildProgram, the compiled artifacts can be queried using clGetProgramInfo.

  1. Determine the size of the binary for each target device: 
    size_t binary_sizes[num_devices];
clGetProgramInfo(program, CL_PROGRAM_BINARY_SIZES, sizeof(size_t) * num_devices, binary_sizes, NULL);
  2. Allocate memory and extract the binaries: 
    unsigned char* binaries[num_devices];
for (cl_uint i = 0; i < num_devices; i++) {
    binaries[i] = (unsigned char*)malloc(binary_sizes[i]);
}
clGetProgramInfo(program, CL_PROGRAM_BINARIES, sizeof(unsigned char*) * num_devices, binaries, NULL);

The format of the returned binary depends on the platform:

  • NVIDIA: Typically an ELF container holding PTX (Parallel Thread Execution) text, SASS (streaming assembler) binary, or both.
  • AMD: An ELF container enclosing AMD IL, LLVM Bitcode, or target-specific GCN/RDNA ISA.
  • Intel: An ELF file containing Intel GEN ISA bytecode or intermediate SPIR-V.

Inspecting NVIDIA PTX and SASS

NVIDIA provides compiler flags and command-line utilities to inspect intermediate PTX and raw SASS assembly:

  • Compiler Options: Pass -cl-nv-verbose into the options parameter of clBuildProgram. The build log (retrievable via clGetProgramInfo with CL_PROGRAM_BUILD_LOG) will output register counts, shared memory usage, and spill statistics.
  • Disassembling Binaries: Save the binary retrieved from clGetProgramInfo to disk and run cuobjdump: 
    # Extract PTX intermediate assembly
cuobjdump --dump-ptx kernel.bin

# Extract SASS machine ISA
cuobjdump --dump-sass kernel.bin

Inspecting AMD GCN and RDNA ISA

AMD developers can dump machine ISA and compiler transformations using environment variables or dedicated toolchains:

  • Environment Variables: Set runtime environment variables prior to running the host application:
    • GPU_DUMP_CODE_OBJECT=1: Dumps the compiled .bin file to the current directory.
    • AMD_OCL_BUILD_OPTIONS_APPEND="-save-temps": Writes intermediate LLVM IR and disassembled ISA files to disk.
  • Offline Compilers and Disassemblers:
    • Use llvm-objdump from the ROCm installation on saved binaries: 
      llvm-objdump -d --mcpu=gfx1030 kernel.bin
    • AMD's Radeon Developer Tool Suite (including the Radeon GPU Profiler) provides graphical visualization of the compiled ISA, instruction timing, and VGPR/SGPR register allocation.

Inspecting Intel GEN ISA and SPIR-V

Intel targets support extraction of both SPIR-V intermediate code and final GEN execution unit instructions:

  • SPIR-V Generation: If using modern OpenCL (2.1+) or the cl_khr_spir extension, compile kernels into intermediate SPIR-V offline using the clang compiler with the -target spir64 flag, or use clspv to generate SPIR-V binaries. Disassemble them using: 
    spirv-dis kernel.spv -o kernel.spvasm
  • Intel Graphics Compiler (IGC) Flags: Pass the following flags into clBuildProgram:
    • -cl-intel-dump-asm: Emits the disassembled GEN execution unit instructions.
    • -cl-intel-gtpin-rera: Assists in register allocation debugging.
  • Intel Tools: Intel Advisor and Intel VTune Profiler automatically map high-level OpenCL source code lines directly to the executed assembly instructions in their respective GUI views.

Web-Based Rapid Inspection

For fast inspection without configuring local environments, tools like Compiler Explorer (godbolt.org) support OpenCL C. By selecting the OpenCL language and an appropriate compiler (such as Clang or ROCm), you can view intermediate LLVM IR and target machine code side-by-side with your kernel source code in real time.
