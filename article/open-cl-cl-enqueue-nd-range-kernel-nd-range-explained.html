OpenCL clEnqueueNDRangeKernel NDRange Explained

In OpenCL, the clEnqueueNDRangeKernel function launches a data-parallel kernel over an N-dimensional index space known as the NDRange. This article breaks down how OpenCL defines this index space through specific API parameters, detailing the roles of dimensionality, global execution sizes, local work-group partitioning, and global offsets. Understanding these parameters is essential for effectively mapping parallel computations onto the physical processing cores of an OpenCL device.

The NDRange Concept

The NDRange represents an abstract, N-dimensional grid of independent computational units called work-items. Each work-item executes an instance of the kernel function. In clEnqueueNDRangeKernel, the structure and boundary of this grid are governed by four tightly coupled parameters: work_dim, global_work_offset, global_work_size, and local_work_size.

1. Dimensionality: work_dim

The work_dim parameter is an unsigned integer (cl_uint) specifying the number of dimensions used to describe the work-items in the NDRange.

  • OpenCL supports values of 1, 2, or 3.
  • A 1D range is typically used for linear data structures like vectors.
  • A 2D range is commonly mapped to matrix operations or image processing.
  • A 3D range is suited for volumetric data, 3D simulations, or multi-dimensional tensors.

The value of work_dim dictates the required array length for the subsequent size and offset parameters.

2. Global Problem Size: global_work_size

The global_work_size parameter is a pointer to an array of work_dim unsigned values (size_t). It defines the total number of work-items that will execute the kernel across each dimension.

For example, in a 2D image processing task on a 1920x1080 image, work_dim is 2, and global_work_size would be defined as an array containing {1920, 1080}. The total number of kernel invocations is the product of the values in this array (\(1920 \times 1080 = 2,073,600\) work-items). Within the kernel, each item queries its global coordinate using the built-in function get_global_id(dimension).

3. Work-Group Division: local_work_size

The local_work_size parameter is also a pointer to an array of work_dim unsigned values (size_t). It specifies how the global index space is partitioned into smaller, cooperative clusters called work-groups.

  • Explicit Partitioning: If provided, work-items within the same work-group execute concurrently on the same compute unit, allowing them to share local memory (__local) and synchronize execution via barriers (barrier(CLK_LOCAL_MEM_FENCE)).
  • Automatic Partitioning: If local_work_size is passed as NULL, the OpenCL runtime automatically decides the optimal work-group dimensions based on device capabilities and hardware architecture.
  • Divisibility Constraint: In OpenCL 1.x, each dimension's global_work_size must be an exact integer multiple of its corresponding local_work_size. OpenCL 2.0 introduced non-uniform work-groups, allowing residual work-items to run without padding, though uniform sizes often remain preferred for maximum performance.

Inside the kernel, items identify their position within their specific group using get_local_id(dimension) and query the group's global coordinate using get_group_id(dimension).

4. Global Offset: global_work_offset

The global_work_offset parameter is a pointer to an array of work_dim values (size_t) used to shift the global ID starting values.

  • If set to NULL, the global IDs in each dimension start at 0.
  • If non-null, work-item global IDs start at the offset value rather than 0. For instance, an offset of {100} in a 1D range with a size of {50} assigns global IDs ranging from 100 to 149.
  • Regardless of the global offset, get_local_id() always begins at 0 within each work-group.
