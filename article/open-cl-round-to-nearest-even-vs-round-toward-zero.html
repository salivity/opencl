OpenCL: Round-to-Nearest-Even vs Round-Toward-Zero

In OpenCL, explicit type conversion functions allow developers to convert floating-point data to integers or different precision floats using specified rounding modes. The primary distinction between round-to-nearest-even (_rte) and round-toward-zero (_rtz) lies in how each mode resolves fractional values and tie-breaking scenarios. While _rte rounds to the closest representable value and resolves halfway ties toward the nearest even number to eliminate statistical bias, _rtz strictly truncates fractional values toward zero, mirroring standard C-style casting.

Round-to-Nearest-Even (_rte)

Round-to-nearest-even is the default rounding mode defined by the IEEE 754 floating-point standard. In OpenCL, it is denoted by the _rte suffix in conversion functions (e.g., convert_int_rte(float_val)).

  • Mechanism: The value is rounded to the closest representable integer or floating-point value. If the value falls exactly halfway between two integers (such as 1.5, 2.5, or -3.5), it rounds to whichever adjacent integer has an even least-significant digit.
  • Tie-Breaking Examples:
    • 1.5 rounds to 2
    • 2.5 rounds to 2
    • 3.5 rounds to 4
    • -1.5 rounds to -2
    • -2.5 rounds to -2
  • Purpose and Advantage: By alternating between rounding up and rounding down on exact halves, _rte prevents upward or downward drift in repeated mathematical calculations, significantly reducing cumulative rounding error in scientific and statistical computing.

Round-Toward-Zero (_rtz)

Round-toward-zero performs direct truncation, moving numbers toward zero along the number line. In OpenCL, it is invoked using the _rtz modifier (e.g., convert_int_rtz(float_val)).

  • Mechanism: The fractional part of the number is completely discarded, regardless of how close it is to the next integer. Positive values round downward, while negative values round upward toward zero.
  • Examples:
    • 1.9 rounds to 1
    • 1.1 rounds to 1
    • -1.9 rounds to -1
    • -1.1 rounds to -1
  • Purpose and Advantage: This mode replicates the behavior of standard C-language integer casts (such as (int)my_float). It requires minimal logic on underlying hardware, making it predictable for array indexing, buffer offset computations, and fixed-point data encoding.

Key Differences

  1. Statistical Bias: _rte is statistically unbiased because halfway ties do not favor positive or negative infinity. In contrast, _rtz introduces a systematic directional bias by shrinking magnitudes toward zero.
  2. Behavior on Non-Ties: For non-halfway numbers (like 2.9), _rte moves to the nearest integer (3), whereas _rtz drops the fractional portion entirely (2).
  3. Use Cases: Use _rte for numerical simulations, digital signal processing (DSP), graphics filtering, and matrix operations where numerical stability is required. Use _rtz when calculating discrete indices, slicing data, or replicating standard C/C++ cast behavior on the GPU.
