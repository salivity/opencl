Parallel k-NN Search Implementation in OpenCL

This article examines the primary techniques used to implement parallel k-nearest neighbor (k-NN) search algorithms using the OpenCL framework. Implementing k-NN efficiently on heterogeneous hardware, such as GPUs and multi-core CPUs, requires optimizing memory bandwidth, restructuring search algorithms for massive concurrency, and minimizing synchronization overhead. The following sections outline the essential strategies—from brute-force matrix optimizations to spatial acceleration structures—that maximize parallel k-NN performance in OpenCL.

Work-Item and NDRange Mapping

The fundamental brute-force (exhaustive) k-NN approach calculates the Euclidean distance between every query point and every reference point. In OpenCL, this is parallelized across an NDRange grid. The standard mapping assigns one OpenCL work-item to compute distances for a single query point across all reference points, or maps a 2D work-group grid where dimensions correspond to blocks of queries and references. This fine-grained decomposition ensures high occupancy across GPU compute units.

Tiling with Local Memory

Global memory latency is often the primary bottleneck in parallel distance calculations. To resolve this, OpenCL implementations use tiling strategies via the __local address space. A work-group loads a tile of reference points and a tile of query points into high-speed on-chip local memory cooperatively. Work-items then calculate pairwise distances against this cached subset before synchronizing with a barrier(CLK_LOCAL_MEM_FENCE) and loading the next tile. This drastically reduces global memory transactions by reusing data across adjacent threads.

SIMD Vectorization

Data points in k-NN often represent feature vectors with multiple dimensions (e.g., coordinates in 3D, 4D, or higher feature spaces). OpenCL provides built-in vector types such as float4, float8, and float16. Organizing feature data into Structure-of-Arrays (SoA) and loading coordinates into these native vector types enables the compiler to generate Single Instruction, Multiple Data (SIMD) operations. This maximizes arithmetic throughput during pairwise distance calculations (e.g., fused multiply-add operations via fma).

Parallel Selection and Heap Strategies

Finding the nearest \(k\) elements out of \(N\) distances without sorting the entire array is critical to maintaining high throughput:

  • Per-Thread Priority Queues: For very small values of \(k\) (e.g., \(k \le 16\)), each work-item can maintain a small max-heap or sorted insertion list in private registers. As new distances are computed, they are compared against the current worst candidate in constant or logarithmic time.
  • Truncated Bitonic Sort: For moderate \(k\) values, distances computed by a work-group are loaded into local memory, where a parallel bitonic sorting network sorts and prunes the candidates iteratively.
  • Radix Select: For large sets, parallel radix selection algorithms partition distance values across work-groups, isolating the \(k\)-smallest candidates in linear time without requiring a full sort.

Stackless Tree Traversal

While brute-force k-NN scales well on GPUs for small datasets or very high dimensions, spatial indexing structures such as k-d trees, octrees, and Bounding Volume Hierarchies (BVH) are preferred for low-dimensional, large-scale data. Standard recursive tree traversal is inefficient on GPUs due to divergent branch execution and lack of a traditional call stack.

To overcome this in OpenCL:

  • Flattened Arrays: Trees are linearized into flat arrays stored in __global memory, where node links are represented by integer indices.
  • Stackless Traversal (Rope Trees): Nodes include "rope" or escape pointers that point directly to the next node to visit upon miss or completion, eliminating the need for a traversal stack.
  • Fixed-Size Register Stacks: When escape pointers are not viable, trees are traversed using small, bit-packed integer stacks held entirely in thread-private registers to avoid spilling to global memory.

Uniform Spatial Grids

For spatial domains with uniform point distribution, uniform grid binning offers an alternative to tree structures. The reference dataset is partitioned into 3D cells via an OpenCL prefix sum (scan) and sort pipeline, creating an indexed grid. Each work-item searches only the cell containing the query point and the immediately adjacent neighboring cells. This approach minimizes divergence because neighbor-cell offsets are regular, deterministic, and map cleanly to parallel memory access patterns.
