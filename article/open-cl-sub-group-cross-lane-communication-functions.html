OpenCL Sub-Group Cross-Lane Communication Functions

OpenCL sub-groups execute work-items concurrently as hardware-level SIMD lanes, enabling high-performance intra-group data sharing without the overhead of local memory barriers. This article outlines the built-in OpenCL C functions that enable cross-lane communication within a sub-group, including broadcast, shuffle, scan, reduction, and vote operations.

Sub-Group Broadcast

The broadcast function reads a value from a single specific lane (work-item) and distributes it to all other lanes within the active sub-group.

  • sub_group_broadcast(T x, uint sub_group_local_id)
    Returns the value of x evaluated by the work-item whose sub-group local ID matches sub_group_local_id. The target ID must be uniform across the calling work-items.

Shuffle Functions

Shuffle functions enable flexible cross-lane exchanges where different work-items can read values from dynamically specified or relative lane positions without accessing local memory. These are defined primarily in OpenCL 2.1+, OpenCL 3.0, and the cl_khr_subgroup_shuffle extension.

  • sub_group_shuffle(T x, uint current_local_id)
    Enables arbitrary cross-lane indexing. Each calling work-item receives the value x from the lane specified by current_local_id.
  • sub_group_shuffle_down(T current, T next, uint delta)
    Shifts data across lanes by decreasing indices. The calling work-item receives the value of current from the lane at index local_id + delta. If the index exceeds the sub-group size, it wraps or draws from the next parameter depending on the overloaded signature.
  • sub_group_shuffle_up(T previous, T current, uint delta)
    Shifts data across lanes by increasing indices. The calling work-item receives the value from index local_id - delta.
  • sub_group_shuffle_xor(T x, uint mask)
    Exchanges data between lanes determined by a bitwise XOR of the caller's lane ID and the supplied mask. This is widely used for butterfly reduction trees and fast Fourier transforms (FFT).

Reductions and Scans

Reductions and scans communicate data across all lanes to compute aggregate values collaboratively. The operation [op] can be add, min, or max.

  • sub_group_reduce_[op](T x)
    Computes the reduction of x across all work-items in the sub-group and returns the final scalar result to all work-items.
  • sub_group_scan_inclusive_[op](T x)
    Performs an inclusive prefix scan across the sub-group. The returned value for lane \(i\) includes the elements of all lanes from \(0\) up to and including \(i\).
  • sub_group_scan_exclusive_[op](T x)
    Performs an exclusive prefix scan across the sub-group. The returned value for lane \(i\) includes the sum/extremum of elements from lane \(0\) up to \(i - 1\).

Vote and Ballot Functions

Vote and ballot operations evaluate condition states across multiple lanes simultaneously, communicating boolean evaluations across the entire sub-group.

  • sub_group_all(int predicate)
    Returns a non-zero value to all lanes if predicate evaluates to non-zero for every active work-item in the sub-group.
  • sub_group_any(int predicate)
    Returns a non-zero value if predicate evaluates to non-zero for at least one active work-item.
  • sub_group_ballot(int predicate)
    Collects the boolean predicate from each lane and returns a bitmask (typically a uint4) representing the status of each lane.
  • sub_group_elect()
    Elects a single active work-item (the one with the lowest local ID) to return true, while all other work-items return false, useful for single-lane divergence control.
