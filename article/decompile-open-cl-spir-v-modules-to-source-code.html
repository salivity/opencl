Decompile OpenCL SPIR-V Modules to Source Code

SPIR-V serves as the standard binary intermediate representation for parallel compute and graphics, utilized heavily in OpenCL and Vulkan ecosystems. Recovering high-level source code from an OpenCL SPIR-V binary is essential for debugging, performance analysis, and security auditing. While translating low-level bytecode back into fully formed OpenCL C presents challenges due to lost metadata during compilation, several specialized tools, disassemblers, and translation layers make it possible to decompile or disassemble OpenCL SPIR-V modules into readable formats.

SPIRV-Cross

Maintained under the Khronos Group umbrella, SPIRV-Cross is one of the most widely used tools for parsing and converting SPIR-V binaries. Its primary design goal is cross-compilation between shader languages. While its primary targets are GLSL, MSL (Metal Shading Language), HLSL, and raw C++, it can process compute shaders originating from OpenCL kernels.

  • Capabilities: Reconstructs complex control flow, optimizes variable scopes, and translates intermediate compute representations into standard high-level shader languages or C++ source code.
  • Use Case: Best suited when you need syntactically valid high-level source code to port or inspect compute pipeline logic.

SPIRV-Tools (spirv-dis)

The official SPIRV-Tools suite includes spirv-dis, the standard disassembler for SPIR-V modules. Rather than attempting to reconstruct high-level C-like syntax, spirv-dis converts the binary representation into human-readable SPIR-V text assembly.

  • Capabilities: Produces exact, instruction-by-instruction text representations preserving all opcodes, types, and embedded debug symbols (such as OpName and OpLine if unstripped).
  • Use Case: Ideal when high-fidelity instruction analysis is required without the artifacts or potential syntax mismatches introduced by high-level decompiler heuristics.

LLVM SPIR-V Translator (llvm-spirv)

OpenCL drivers heavily integrate LLVM for kernel compilation. The LLVM SPIR-V Translator acts as a bi-directional translation layer between LLVM Intermediate Representation (LLVM IR) and SPIR-V.

  • Capabilities: Using the command-line flag -r, the tool reverses the translation, converting an input SPIR-V module back into LLVM bitcode (.bc) or human-readable LLVM IR (.ll).
  • Integration with Decompilers: Once converted back to LLVM IR, standard LLVM-based decompilers (such as llvm-cbe for C backend reconstruction) or static analyzers can be applied to generate C-like source code.

General-Purpose Reverse Engineering Frameworks

Dedicated binary analysis suites offer extensible support for parsing and decompiling SPIR-V binaries:

  • Ghidra with SPIR-V Extensions: Community plugins add SPIR-V loader and processor definitions to the NSA’s open-source Ghidra framework. This allows Ghidra's decompiler engine to generate pseudocode approximations of compute kernels.
  • IDA Pro: Third-party loaders and processor modules exist for IDA Pro, enabling disassembling and control-flow graph (CFG) mapping for OpenCL compute binaries.

Practical Limitations of SPIR-V Decompilation

When decompiling OpenCL SPIR-V back to source code, several constraints apply:

  1. Stripped Metadata: Unless the binary was compiled with debug flags enabled, high-level identifiers (kernel argument names, variable names, and comments) are permanently discarded during the initial compilation phase.
  2. Memory Layout and Pointers: OpenCL makes specific use of address spaces (such as __global, __local, and __constant). Decompilers may translate these as raw pointers or generic memory offsets rather than native OpenCL address space qualifiers.
  3. Structured Control Flow: OpenCL kernels containing complex divergence or unstructured loops might decompile into heavily nested conditional statements or explicit goto blocks rather than the original loops.
