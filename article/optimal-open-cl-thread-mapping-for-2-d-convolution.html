Optimal OpenCL Thread Mapping for 2D Convolution

This article outlines the optimal thread mapping strategies for implementing 2D image convolution in OpenCL, focusing on global and local NDRange dimensions, work-group sizing, local memory tiling, and thread coarsening to maximize memory throughput and compute utilization.

1. Global NDRange and Dimension Mapping

In 2D convolution, each output pixel depends on a neighborhood of input pixels defined by the filter kernel size. The standard OpenCL paradigm maps the global execution space directly to the 2D image domain:

  • Dimension 0 (x): Image Width (columns)
  • Dimension 1 (y): Image Height (rows)

Each work-item queries its global position using:

int x = get_global_id(0);
int y = get_global_id(1);

Ensure that the global work size in the x dimension is rounded up to the nearest multiple of the local work-group size to prevent tail-effect stalls and memory misalignment. Any out-of-bounds work-items must simply return early before memory accesses.

2. Work-Group (Local NDRange) Sizing

Work-groups must align with the target architecture’s hardware execution units—specifically warps (32 threads on NVIDIA) or wavefronts (32 or 64 threads on AMD/Intel).

  • Recommended Dimensions: 16x16 (256 threads) or 32x8 (256 threads).
  • Work-Group Total Size: 128 to 256 work-items represents the sweet spot for maximizing occupancy without exhausting hardware registers or shared local memory (SLM).
  • Square vs. Rectangular: A square configuration like 16x16 minimizes the boundary-to-area ratio (perimeter-to-surface area), which reduces the relative overhead of halo pixel loading when using local memory.

3. Tiling with Local Memory (__local)

Repeatedly reading neighboring pixels from global memory creates a major memory bandwidth bottleneck. For an \(N \times N\) filter, an unoptimized kernel reads each pixel up to \(N^2\) times.

To achieve optimal throughput:

  1. Allocate Local Buffer: Reserve a shared local array sized \((W_{\text{local}} + 2R) \times (H_{\text{local}} + 2R)\), where \(R\) is the filter radius (\(\lfloor N / 2 \rfloor\)).
  2. Cooperative Loading: Have all work-items within the work-group collaborate to load both internal pixels and the surrounding halo region from global memory into __local memory.
  3. Synchronize: Call barrier(CLK_LOCAL_MEM_FENCE) to guarantee all data is resident in local memory.
  4. Compute: Evaluate the convolution using solely low-latency local memory or registers.

4. Work-Item Coarsening (Thread Merging)

Instead of assigning one work-item per single output pixel, optimal performance is frequently achieved by mapping one work-item to multiple adjacent output pixels (e.g., \(1 \times 2\), \(1 \times 4\), or \(2 \times 2\)).

  • Vectorization: Processing 4 horizontal pixels per thread allows the use of vectorized data types (float4, uchar4), optimizing memory bus utilization through coalesced 128-bit loads and stores.
  • Register Reuse: Adjacent pixels share substantial filter overlap. Holding intermediate input values in hardware registers rather than re-fetching them from local memory reduces local memory bank conflicts and lowers arithmetic instruction counts.
  • Adjusted Grid: When coarsening by a factor of 4 along the horizontal axis, the global NDRange in dimension 0 is scaled down to Width / 4.

5. Hardware Textures (image2d_t) vs. Buffers

OpenCL offers two distinct approaches for 2D convolution data paths:

Option A: OpenCL Image Objects (image2d_t)

  • Mechanism: Routes memory through dedicated GPU texture pipelines, which feature hardware-level 2D spatial caches and built-in out-of-bounds border addressing (clamping).
  • Best For: Small to medium kernels (e.g., \(3 \times 3\), \(5 \times 5\)) and pipelines requiring automatic border clamping with minimal boilerplate. Thread mapping remains a straightforward 1:1 mapping with a 16x16 local work-group.

Option B: Standard Buffers (__global) with Local Memory

  • Mechanism: Relies on manual software cache management in __local memory.
  • Best For: Larger filter kernels (\(7 \times 7\) and above), separable filters, and integer workloads where texture units might introduce unwanted precision conversions or lack optimal performance.

Summary of Optimal Settings

Component Optimal Strategy
NDRange Dimensions 2D (x = Width, y = Height)
Local Work-Group Size 16x16 (256 threads)
Memory Path (Small Filters) image2d_t using built-in samplers
Memory Path (Large Filters) __global buffer with __local tiling and halo loading
