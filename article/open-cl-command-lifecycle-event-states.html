OpenCL Command Lifecycle Event States

In OpenCL, asynchronous commands submitted to a command-queue are tracked using event objects (cl_event). This article provides a concise overview of the distinct execution status states that an OpenCL command moves through during its lifecycle, from initial creation and queue placement to execution on a device and final completion.

When an OpenCL API function enqueues a command (such as clEnqueueNDRangeKernel or clEnqueueReadBuffer), it can return an event object. Developers query this object via clGetEventInfo with the CL_EVENT_COMMAND_EXECUTION_STATUS parameter to monitor the command's progression. The command progresses sequentially through the following states:

1. CL_QUEUED

CL_QUEUED is the initial state assigned immediately when a command is enqueued into a command-queue by the host application. At this stage, the command resides purely in software on the host side and has not yet been flushed or delivered to the targeted OpenCL compute device.

2. CL_SUBMITTED

A command transitions to CL_SUBMITTED when it has been transferred from the host queue to the device's processing pipeline. While the device now possesses the command, execution has not yet started. Commands often remain in this state if they are waiting for prerequisite events in an event wait list to reach CL_COMPLETE, or if prior tasks in an in-order command-queue have not finished.

3. CL_RUNNING

The CL_RUNNING state signifies that all dependencies have cleared and the device has actively begun executing the command. For a kernel command, this means work-items are actively processing on compute units; for a memory transfer command, data is actively being copied between host and device or between device buffers.

4. CL_COMPLETE

CL_COMPLETE indicates that the command has finished execution successfully. At this point, any output data is guaranteed to be available according to OpenCL memory consistency rules, and any downstream commands waiting on this event are unblocked to proceed.

5. Negative Values (Error States)

If a command fails at any point during its lifecycle, its execution status transitions to a negative integer value rather than CL_COMPLETE. These negative values correspond directly to standard OpenCL error codes (such as CL_OUT_OF_RESOURCES or CL_EXEC_STATUS_ERROR_FOR_EVENTS_IN_WAIT_LIST). When a command fails, any dependent commands waiting on its event are typically terminated with an error as well.
