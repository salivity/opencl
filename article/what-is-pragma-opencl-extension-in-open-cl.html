What Is pragma OPENCL EXTENSION in OpenCL?

In OpenCL kernel programming, hardware capabilities and language features often vary across different compute devices and vendor platforms. This article explains the purpose of the #pragma OPENCL EXTENSION directive, detailing how it enables or disables optional language features, ensures hardware compatibility, and controls compiler behavior during runtime kernel compilation.

The primary purpose of #pragma OPENCL EXTENSION is to tell the OpenCL compiler to selectively enable or disable optional extensions and vendor-specific features within OpenCL C kernel source code. Because OpenCL runs on a wide array of architectures—such as CPUs, GPUs, and FPGAs—not all hardware supports every advanced capability. Core specifications define mandatory features, while optional capabilities (such as double-precision floating-point arithmetic or specific hardware intrinsics) are packaged as extensions.

The directive uses the following syntax:

#pragma OPENCL EXTENSION extension_name : behavior

The extension_name represents the specific extension (for example, cl_khr_fp64), and behavior typically dictates how the compiler handles it:

  • enable: Instructs the compiler to allow types, built-in functions, and tokens provided by the extension. If the target device does not support the extension, the compiler produces a warning or error.
  • disable: Instructs the compiler to forbid the use of any functions or types introduced by the specified extension.
  • all: Can be combined with disable (i.e., #pragma OPENCL EXTENSION all : disable) to turn off all optional extensions, enforcing strict adherence to core OpenCL C.

A common application of this directive is enabling double-precision floating-point support. In OpenCL versions where 64-bit floating-point math is not part of the standard core, using the double primitive type requires enabling the corresponding extension:

#pragma OPENCL EXTENSION cl_khr_fp64 : enable

__kernel void process_data(__global double *input, __global double *output) {
    int id = get_global_id(0);
    output[id] = input[id] * 2.0;
}

Without the directive, the compiler will fail with an error when encountering the double keyword or double-precision intrinsic functions, even if the underlying device supports 64-bit precision.

Proper development practice requires querying device capabilities on the host side first using clGetDeviceInfo with the CL_DEVICE_EXTENSIONS flag. Once the host confirms that the target device supports the required extension, the kernel can safely use #pragma OPENCL EXTENSION to activate the feature without compilation failures.
