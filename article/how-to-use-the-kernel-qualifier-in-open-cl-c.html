How to Use the __kernel Qualifier in OpenCL C

The __kernel qualifier in OpenCL C identifies a function as an entry point intended to be executed on an OpenCL device from a host application. This article provides a concise overview of how __kernel is applied, the syntax requirements governing its use, the fundamental restrictions imposed on kernel functions, and how they differ from standard helper functions within an OpenCL program.

Defining a Kernel Function

In OpenCL C, the __kernel qualifier (or its shorthand equivalent, kernel) is placed immediately before the function's return type. It signals to the OpenCL compiler that this function can be queued for execution on a compute device using host-side APIs such as clEnqueueNDRangeKernel.

__kernel void vector_add(__global const float *a, 
                         __global const float *b, 
                         __global float *result) 
{
    int id = get_global_id(0);
    result[id] = a[id] + b[id];
}

Mandatory Rules and Restrictions

When declaring and defining functions with __kernel, the OpenCL C specification enforces several strict rules:

  • Return Type Must Be void: A kernel function cannot return a value. Any output produced by the kernel must be written to memory passed via pointer arguments.
  • Host-Only Invocation: Functions declared with __kernel can only be invoked by the host program. A kernel function cannot call another kernel function within the device code.
  • Pointer Argument Address Spaces: Any pointer passed as an argument to a kernel function must be explicitly qualified with an address space: __global, __local, or __constant. Pointer arguments cannot point to the __private address space.
  • Non-Pointer Arguments: Scalar or vector values passed by value are allocated in the private address space by default and do not require an address space qualifier.
  • No Variable Argument Lists: Kernel functions cannot use variadic arguments (...).

Kernel Functions vs. Helper Functions

OpenCL C allows standard C-style functions to be defined alongside kernels to act as helper or utility routines:

  • Kernels (__kernel): Visible to the host, directly scheduled for parallel execution, must return void, and serve as the root of the device-side execution tree.
  • Helper Functions (No __kernel): Callable only by kernels or other helper functions on the device. They can return concrete data types (such as int, float, or custom structures) and are often inlined by the OpenCL compiler for performance optimization.
