OpenCL Child Kernel Enqueue Built-in Functions

In OpenCL 2.0 and later versions, device-side enqueue allows a running kernel (parent) to launch another kernel (child) directly on the device without host intervention. This capability is powered primarily by the enqueue_kernel built-in function, along with auxiliary functions that manage execution ranges, device queues, and synchronization events. By shifting task scheduling entirely to the GPU or accelerator, these functions enable nested parallelism, dynamic load balancing, and lower latency.

The Primary Function: enqueue_kernel

The fundamental built-in function used to enqueue a child kernel directly from a parent kernel is enqueue_kernel. It is heavily overloaded in the OpenCL C shading language to support various execution configurations, synchronization requirements, and local memory allocations.

The standard signature format is:

int enqueue_kernel(
    queue_t queue,
    kernel_enqueue_flags_t flags,
    const ndrange_t ndrange,
    void (^block)(void)
);

For workloads requiring event handling and dynamic local memory, extended overloads accept wait lists, event handles, and size parameters for local arguments:

int enqueue_kernel(
    queue_t queue,
    kernel_enqueue_flags_t flags,
    const ndrange_t ndrange,
    uint num_events_in_wait_list,
    const clk_event_t *event_wait_list,
    clk_event_t *event_ret,
    void (^block)(local void *, ...),
    uint size0, ...
);

Key arguments include:

  • queue: The device command-queue where the child kernel is submitted.
  • flags: Execution flags such as CLK_ENQUEUE_FLAGS_NO_WAIT, CLK_ENQUEUE_FLAGS_WAIT_KERNEL, or CLK_ENQUEUE_FLAGS_WAIT_WORK_GROUP, specifying synchronization behavior with respect to the parent work-items.
  • ndrange: An ndrange_t structure defining the index space and work-group sizing.
  • block: The child kernel code expressed as a block (a closure-like construct in OpenCL C).

Queue Acquisition: get_default_device_queue

To provide the queue_t argument required by enqueue_kernel, OpenCL provides the built-in function:

  • queue_t get_default_device_queue(void): Returns the default device command-queue configured on the host. This avoids passing queue handles explicitly through kernel arguments.

Index Space Configuration: ndrange_*D Built-ins

Device-side enqueue cannot use host-side runtime APIs like clEnqueueNDRangeKernel to define dimensions. Instead, OpenCL C provides built-in constructors to generate ndrange_t objects:

  • ndrange_1D(size_t global_work_size) and ndrange_1D(size_t global_work_size, size_t local_work_size)
  • ndrange_2D(const size_t global_work_size[2]) and ndrange_2D(const size_t global_work_size[2], const size_t local_work_size[2])
  • ndrange_3D(const size_t global_work_size[3]) and ndrange_3D(const size_t global_work_size[3], const size_t local_work_size[3])

Variants with global work offsets are also supported (e.g., specifying global_work_offset).

Event and Synchronization Functions

When child kernels have execution dependencies, several built-in functions manage synchronization directly within the device:

  • create_user_event(): Creates a device-side user event to manually signal execution readiness.
  • set_user_event_status(clk_event_t event, int status): Sets the execution status of a user event (e.g., CL_COMPLETE), unblocking any child kernels waiting on it.
  • retain_event(clk_event_t event): Increments the reference count of an event.
  • release_event(clk_event_t event): Decrements the reference count of an event, freeing resources once it hits zero.
  • enqueue_marker(queue_t queue, uint num_events, const clk_event_t *wait_list, clk_event_t *event_ret): Enqueues a marker command into the device queue to coordinate execution points between different child submissions.
