Native Vector Data Types in OpenCL C

OpenCL C provides built-in vector data types designed to map directly onto modern SIMD (Single Instruction, Multiple Data) architectures, GPUs, and vector extensions of CPUs. These types enable developers to perform parallel computations on grouped data elements efficiently. In OpenCL C, vector types are formed by pairing a base scalar type with a specific vector length, allowing native support for vector arithmetic, logical operations, and memory loads and stores.

Supported Vector Lengths

Vector types in OpenCL C are available in specific element counts denoted by \(n\), where \(n\) can be:

  • 2
  • 3
  • 4
  • 8
  • 16

Note that OpenCL does not provide generic or arbitrary-length vectors; only these predefined widths are recognized as native vector types.

Native Vector Types by Base Type

OpenCL C defines vector representations for both integer and floating-point scalar types:

Signed Integer Vectors

  • char (8-bit signed integer): char2, char3, char4, char8, char16
  • short (16-bit signed integer): short2, short3, short4, short8, short16
  • int (32-bit signed integer): int2, int3, int4, int8, int16
  • long (64-bit signed integer): long2, long3, long4, long8, long16

Unsigned Integer Vectors

  • uchar (8-bit unsigned integer): uchar2, uchar3, uchar4, uchar8, uchar16
  • ushort (16-bit unsigned integer): ushort2, ushort3, ushort4, ushort8, ushort16
  • uint (32-bit unsigned integer): uint2, uint3, uint4, uint8, uint16
  • ulong (64-bit unsigned integer): ulong2, ulong3, ulong4, ulong8, ulong16

Floating-Point Vectors

  • float (32-bit single-precision): float2, float3, float4, float8, float16
  • double (64-bit double-precision): double2, double3, double4, double8, double16 (Requires OpenCL FP64 extension or core FP64 support)
  • half (16-bit half-precision): half2, half3, half4, half8, half16 (Supported natively for storage and conversions, or for computation where the cl_khr_fp16 extension is supported)

Memory Alignment and Size Rules

Vector types have explicit alignment rules in memory:

  • A vector of size \(n\) elements has an alignment matching its total byte size, rounded up to the nearest power of two.
  • 3-component vectors (float3, int3, etc.) have the same size and memory alignment requirements as 4-component vectors (float4, int4). For example, sizeof(float3) is equal to \(16\) bytes, matching sizeof(float4), with the fourth component serving as padding in memory layouts.
  • 8-component vectors align to 8 times the base scalar size, and 16-component vectors align to 16 times the base scalar size.

Accessing Vector Components

OpenCL C supports component access using dot notation:

  • Positional (up to 4 elements): .x, .y, .z, .w (e.g., vec.xy)
  • Color notation (up to 4 elements): .r, .g, .b, .a
  • Numeric indices (up to 16 elements): .s0, .s1, ..., .s9, .sA, .sB, .sC, .sD, .sE, .sF (case-insensitive)
  • High/Low/Odd/Even access: .hi, .lo, .even, .odd for splitting and restructuring vectors.
