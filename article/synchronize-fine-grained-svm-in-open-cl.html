Synchronize Fine-Grained SVM in OpenCL

Fine-grained Shared Virtual Memory (SVM) in OpenCL allows the host CPU and OpenCL devices to share a unified virtual address space and read or write to overlapping memory regions concurrently. Synchronizing fine-grained SVM buffers requires identifying device capability levels, allocating memory with appropriate flags, employing either memory fences or atomic operations for cache coherency, and managing execution boundaries with OpenCL events.

Step 1: Query Device SVM Capabilities

Before allocating memory, verify the device's level of fine-grained support by calling clGetDeviceInfo with the CL_DEVICE_SVM_CAPABILITIES parameter.

Check for two distinct feature flags:

  • CL_DEVICE_SVM_FINE_GRAINED_BUFFER: Indicates the device can access byte-level shared virtual memory concurrently without explicit map or unmap operations.
  • CL_DEVICE_SVM_ATOMICS: Indicates the device supports hardware-level atomic operations shared between the host CPU and the OpenCL device.

Step 2: Allocate the Fine-Grained SVM Buffer

Allocate the memory region using clSVMAlloc. You must pass the CL_MEM_SVM_FINE_GRAINED_BUFFER flag. If the target device supports it and your synchronization pattern requires lock-free concurrency, also pass CL_MEM_SVM_ATOMICS.

void* svm_ptr = clSVMAlloc(
    context,
    CL_MEM_READ_WRITE | CL_MEM_SVM_FINE_GRAINED_BUFFER | CL_MEM_SVM_ATOMICS,
    buffer_size,
    0
);

Step 3: Pass the Pointer to the Kernel

Bind the allocated buffer to your kernel using clSetKernelArgSVMPointer. Fine-grained SVM buffers do not require standard cl_mem wrapper objects; the raw host pointer is passed directly to the device.

Step 4: Synchronize Data Access

The mechanism used to synchronize updates between the host and device depends on whether the allocation supports SVM atomics.

Method A: Using Fine-Grained SVM with Atomics

When CL_MEM_SVM_ATOMICS is supported and enabled:

  1. Define atomic synchronization variables within the allocated buffer using standard OpenCL C 2.0 / 3.0 atomic types (e.g., atomic_int).
  2. On the host side, use C11 or C++11 atomic types (std::atomic<int>) mapped directly to the same memory addresses.
  3. Coordinate read/write sequences using acquire-release memory order semantics (memory_order_release when publishing data and memory_order_acquire when consuming data).
  4. Use atomic_work_item_fence within the kernel to guarantee memory visibility across the device and the host.

Method B: Using Fine-Grained SVM without Atomics

If the device supports fine-grained buffers but lacks SVM atomics, the host and device cannot safely perform concurrent writes to the same memory location:

  1. Ensure the host and device do not access the exact same memory locations simultaneously, or execute access in distinct phases.
  2. Use command queue markers, event waits, or clEnqueueBarrierWithWaitList to establish boundaries between host execution and kernel execution.
  3. Wait on kernel completion events (clWaitForEvents) before allowing the host CPU to read device-written regions.
  4. Call clFinish or wait on an event generated by clEnqueueMarkerWithWaitList to flush operations and ensure cache visibility before switching access roles.

Step 5: Free the Memory

Once kernel execution is complete and all host operations have finished, release the allocated memory region using clSVMFree. Ensure all pending device queues accessing the memory have completed execution before freeing the pointer.
