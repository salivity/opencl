OpenCL RNG: Preventing Parallel Correlation Artifacts

In massively parallel OpenCL simulations, generating statistically sound pseudo-random numbers is critical to obtaining accurate results. When thousands of concurrent work-items generate random values, improper state initialization can cause different execution threads to produce identical or mathematically coupled sequences, resulting in severe correlation artifacts. State generation independence ensures that each parallel thread maintains an isolated, non-overlapping, and statistically orthogonal random stream, preserving the integrity of stochastic calculations such as Monte Carlo methods and molecular dynamics.

In OpenCL architectures, high computational throughput is achieved by scheduling thousands of work-items across multiple Compute Units. Traditional single-threaded pseudo-random number generators (PRNGs), such as standard Linear Congruential Generators (LCGs), rely on a single shared state updated iteratively. If applied naively in OpenCL—either by sharing a state across work-items via global memory or by seeding independent threads with sequential seeds (e.g., base seed plus the global work-item ID)—the generator degrades. Shared state introduces massive synchronization contention and race conditions, while simple offset seeding often leads to phase alignment, where different threads traverse the exact same sequence with a slight time delay.

Correlation artifacts manifest when parallel streams overlap or exhibit cross-thread linear dependencies. In spatial simulations or particle systems, this results in artificial clustering, recurring geometric patterns, or false physical phase transitions. These anomalies occur because multi-dimensional sampling vectors assembled from correlated work-items fall onto a limited set of hyperplanes rather than uniformly populating the sampling space.

State generation independence solves this failure mode through two primary methodologies: counter-based generation and sequence splitting.

Counter-based PRNGs (CBRNGs), such as Philox and Threefry, represent the most effective way to achieve state independence in OpenCL. Unlike iterative state-transition PRNGs, CBRNGs compute the \(n\)-th random number as a cryptographic-like bijection of an arbitrary counter value and a distinct key:

\[\text{Random Value} = f_K(\text{Counter})\]

In an OpenCL kernel, the key can be assigned as a run-wide constant, while the counter is derived directly from unique, invariant thread attributes—typically a combination of get_global_id(), dimension strides, and an iteration step. Because the underlying transformation functions are designed to maximize diffusion and pass stringent empirical tests (such as TestU01), work-items remain statistically independent even when their counter inputs differ by only a single bit. There is no possibility of sequence collision within realistic computational horizons (\(2^{64}\) to \(2^{128}\) evaluations), inherently eliminating cross-lane correlation artifacts.

Alternatively, parameterization and block-splitting methods achieve independence by mathematically partitioning a single vast generator period into disjoint subsequences. Each work-item is assigned a distinct parameter set or an entry point separated by a leap distance larger than the total number of draws the simulation will ever execute. This prevents any work-item from encountering states previously computed by another lane during the simulation lifecycle.

By enforcing state generation independence, OpenCL kernels isolate the computational trajectory of each work-item. This isolation prevents SIMD/SIMT scheduling patterns from imprinting hardware-level execution locks onto the statistical distribution, eliminates false cross-thread resonances, and guarantees that large-scale parallel simulations converge to physically and mathematically correct solutions.
