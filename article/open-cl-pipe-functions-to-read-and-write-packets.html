OpenCL Pipe Functions to Read and Write Packets

OpenCL 2.0 introduced pipes as a memory object to facilitate FIFO (First-In, First-Out) data communication directly between kernels or between different work-items within a kernel without host intervention. This article outlines the built-in functions provided by the OpenCL C shading language that allow kernels to read packets from and write packets to pipes, detailing basic point-to-point packet access, reservation-based mechanisms, and group-level operations.

Basic Packet Access Functions

The most direct way to transfer single data packets to and from a pipe is by using the non-reservation built-in functions:

  • read_pipe(pipe gentype p, gentype *ptr)
    Reads a single packet from the pipe p and copies it into the location referenced by ptr. It returns 0 if the operation is successful and a negative value if the pipe is empty.
  • write_pipe(pipe gentype p, const gentype *ptr)
    Writes a single packet pointed to by ptr to the pipe p. It returns 0 if the packet was successfully written and a negative value if the pipe is full.

Reservation-Based Work-Item Functions

When a work-item needs to read or write multiple packets contiguously, OpenCL uses reservation-based functions to reserve space before committing data.

  • reserve_read_pipe(pipe gentype p, uint num_packets)
    Reserves num_packets to be read from the pipe. Returns a valid reserve_id_t token on success or an invalid token if the requested number of packets cannot be reserved.
  • reserve_write_pipe(pipe gentype p, uint num_packets)
    Reserves space for num_packets to be written to the pipe. Returns a valid reserve_id_t token on success.
  • read_pipe(pipe gentype p, reserve_id_t reserve_id, uint index, gentype *ptr)
    Reads a packet from reserved read space at the offset specified by index into ptr.
  • write_pipe(pipe gentype p, reserve_id_t reserve_id, uint index, const gentype *ptr)
    Writes a packet from ptr into reserved write space at the offset specified by index.
  • commit_read_pipe(pipe gentype p, reserve_id_t reserve_id)
    Commits the read reservation, updating the pipe’s read pointer so that freed space becomes available to writers.
  • commit_write_pipe(pipe gentype p, reserve_id_t reserve_id)
    Commits the write reservation, making the newly written packets visible and available to readers.

Work-Group and Sub-Group Reservation Functions

For coordinated collective operations where an entire work-group or sub-group shares access to a pipe, OpenCL provides group-level variants:

  • work_group_reserve_read_pipe(pipe gentype p, uint num_packets) / sub_group_reserve_read_pipe(pipe gentype p, uint num_packets)
    Collectively reserves a contiguous range of packets to be read by the work-group or sub-group.
  • work_group_reserve_write_pipe(pipe gentype p, uint num_packets) / sub_group_reserve_write_pipe(pipe gentype p, uint num_packets)
    Collectively reserves space for packets to be written by the work-group or sub-group.
  • work_group_commit_read_pipe(pipe gentype p, reserve_id_t reserve_id) / sub_group_commit_read_pipe(pipe gentype p, reserve_id_t reserve_id)
    Collectively commits the group read operation.
  • work_group_commit_write_pipe(pipe gentype p, reserve_id_t reserve_id) / sub_group_commit_write_pipe(pipe gentype p, reserve_id_t reserve_id)
    Collectively commits the group write operation.

Pipe Query Functions

To inspect capacity before or during read/write operations, kernels can query pipes with:

  • get_pipe_num_packets(pipe gentype p)
    Returns the current number of readable packets available in the pipe.
  • get_pipe_max_packets(pipe gentype p)
    Returns the maximum capacity of packets the pipe can hold.
