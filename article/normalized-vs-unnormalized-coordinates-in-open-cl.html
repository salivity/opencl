Normalized vs Unnormalized Coordinates in OpenCL

In OpenCL, image samplers define how image objects are read inside compute kernels, with coordinate normalization serving as a primary configuration setting. This article outlines the fundamental differences between normalized and unnormalized coordinates, compares their behavior with various addressing modes, and explains when to implement each approach in parallel applications.

Coordinate Definitions

OpenCL provides two coordinate systems when declaring a sampler (sampler_t) via the CLK_NORMALIZED_COORDS_TRUE or CLK_NORMALIZED_COORDS_FALSE flags.

  • Normalized Coordinates (CLK_NORMALIZED_COORDS_TRUE): Coordinate values are expressed as floating-point values typically ranging from 0.0f to 1.0f, regardless of the actual dimensions of the image. The coordinate (0.0, 0.0) represents the top-left corner, while (1.0, 1.0) represents the bottom-right corner.
  • Unnormalized Coordinates (CLK_NORMALIZED_COORDS_FALSE): Coordinate values are mapped directly to the actual pixel (or texel) dimensions of the image. For an image of width \(W\) and height \(H\), coordinates range from 0.0f to W along the x-axis and 0.0f to H along the y-axis.

Resolution Independence

The primary functional difference is resolution independence:

  • Normalized coordinates decouple kernel logic from the image dimensions. If an algorithm requires sampling the center of an image, the kernel accesses (0.5f, 0.5f) whether the underlying image is 256x256 or 4096x4096 pixels. This simplifies operations like resizing, texture mapping, and procedural pattern generation.
  • Unnormalized coordinates tie memory access directly to pixel indices. This is ideal for kernels that operate on neighboring pixels using discrete offsets, such as convolution matrices, edge detection, or stencil operations where accessing \((x+1, y)\) is required.

Addressing Modes Compatibility

The choice between normalized and unnormalized coordinates strictly limits the addressing modes available to the OpenCL sampler:

  • Repeat Modes: Sampler addressing modes CLK_ADDRESS_REPEAT and CLK_ADDRESS_MIRRORED_REPEAT can only be used with normalized coordinates. Attempting to use repeat modes with unnormalized coordinates results in undefined behavior or compilation errors.
  • Clamp Modes: Both normalized and unnormalized coordinates support CLK_ADDRESS_CLAMP_TO_EDGE, CLK_ADDRESS_CLAMP, and CLK_ADDRESS_NONE.

Filtering and Texel Centers

Both coordinate modes support nearest-neighbor (CLK_FILTER_NEAREST) and linear (CLK_FILTER_LINEAR) filtering:

  • In unnormalized coordinates, texel centers are located at half-integer coordinates: \((u + 0.5, v + 0.5)\) for integer pixel indices \((u, v)\).
  • In normalized coordinates, texel centers are located at \(((u + 0.5) / W, (v + 0.5) / H)\).

Dedicated GPU texture units handle the address conversion and interpolation hardware-side, meaning there is generally no runtime performance penalty when choosing normalized over unnormalized coordinates.

Summary of Usage

  • Choose normalized coordinates when mapping textures across arbitrary geometries, implementing wrapping/repeating textures, or writing algorithms that must run unmodified across varying image resolutions.
  • Choose unnormalized coordinates when porting array-based algorithms to images, performing neighborhood filtering, or working with explicit pixel grids where coordinate math is directly linked to integer pixel boundaries.
