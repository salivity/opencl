Pinned vs Mapped Memory in OpenCL

In OpenCL host-device communication, pinned memory and mapped memory are closely related concepts that serve distinct roles in optimizing data transfers. Pinned memory refers to host system memory that is locked into physical RAM to enable hardware Direct Memory Access (DMA), preventing the operating system from paging it out to disk. Mapped memory, on the other hand, is a software mechanism that exposes a buffer's address space directly to the host application via a standard pointer, eliminating the need for explicit read and write transfer calls. Understanding the distinction between this memory state (pinned) and this access method (mapped) is essential for achieving high-throughput, low-latency heterogeneous computing.

What Is Pinned Memory?

Standard host memory allocated via system calls like malloc is pageable, meaning the operating system can swap pages between physical RAM and storage. Because a discrete device (such as a GPU) cannot safely access pageable memory via Direct Memory Access without risking invalid memory access, traditional transfers require an intermediate step: the OpenCL runtime copies data from pageable host memory into an internal, page-locked staging buffer before initiating the DMA transfer to the device.

Pinned memory (page-locked memory) avoids this staging overhead. By allocating a buffer with the CL_MEM_ALLOC_HOST_PTR flag, OpenCL requests memory that the operating system guarantees will remain fixed in physical RAM. Because this memory location is guaranteed not to move, the device's DMA controller can read from or write to it directly over the PCIe bus, achieving the maximum possible physical transfer bandwidth.

What Is Mapped Memory?

Mapped memory is an access pattern rather than a physical memory type. Normally, moving data between host memory and an OpenCL buffer requires calling clEnqueueReadBuffer or clEnqueueWriteBuffer. These functions perform explicit data copies between host-allocated arrays and OpenCL memory objects.

With memory mapping, you call clEnqueueMapBuffer. The OpenCL runtime maps the buffer's memory range into the host process's virtual address space and returns a native C/C++ pointer. The CPU can then read or write to that pointer directly using standard operations. Once the host is finished accessing the pointer, it calls clEnqueueUnmapMemObject to synchronize the changes and release host access, allowing the OpenCL device to safely use the buffer again.

Key Differences

Aspect Pinned Memory Mapped Memory
Fundamental Nature A physical memory state (page-locked allocation). An access mechanism (virtual address mapping).
Primary Purpose Eliminates CPU-side staging copies to maximize DMA transfer speeds. Provides direct pointer access to buffer contents without explicit read/write calls.
OpenCL Flags/APIs clCreateBuffer with CL_MEM_ALLOC_HOST_PTR. clEnqueueMapBuffer, clEnqueueMapImage, and clEnqueueUnmapMemObject.
OS Interaction Prevents the OS kernel from paging out memory to disk. Updates the host process page table to map buffer pages to user-space virtual addresses.

How They Work Together

Pinned memory and mapped memory are frequently used in tandem to achieve "zero-copy" behavior:

  1. Allocation: The host creates a buffer using clCreateBuffer with the CL_MEM_ALLOC_HOST_PTR flag. This creates a pinned buffer in host-accessible memory.
  2. Mapping: The host calls clEnqueueMapBuffer with CL_MAP_WRITE or CL_MAP_READ to obtain a direct pointer to this pinned memory.
  3. Execution: The CPU populates or reads the data directly through the returned pointer, avoiding any intermediate buffers.
  4. Unmapping: The host calls clEnqueueUnmapMemObject. For discrete GPUs, this signals that the host has finished writing, allowing the device to DMA the data across PCIe. For unified memory architectures (like integrated GPUs or APUs), unmapping simply synchronizes caches without copying any data across a bus, achieving true zero-copy execution.
