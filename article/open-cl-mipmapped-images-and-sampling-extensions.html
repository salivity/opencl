OpenCL Mipmapped Images and Sampling Extensions

This article provides an overview of how mipmapped images operate within the OpenCL framework and outlines the specific extensions that enable mipmap sampling and manipulation. You will learn how OpenCL handles level-of-detail (LOD) texture chains, how host-side image descriptors configure mipmap pyramids, and how the OpenCL extension framework exposes explicit LOD and gradient-based sampling built-ins inside kernel code.

How Mipmapped Images Function in OpenCL

A mipmap consists of a pre-calculated sequence of images, each representing the same graphic at progressively lower resolutions. In OpenCL, mipmapped images reduce aliasing artifacts and optimize memory bandwidth by allowing the compute device to sample from the resolution level that most closely matches the sampling rate of the target geometry or compute grid.

To utilize mipmaps on the host side, applications populate the num_mip_levels field within the cl_image_desc structure when invoking clCreateImage. A value greater than one instructs the OpenCL runtime to allocate memory for the full chain down to the 1x1 pixel base.

Once created, the behavior of mipmap sampling is controlled by the sampler. In OpenCL, samplers configured for mipmapped images incorporate additional properties:

  • Mip Filter Mode: Dictates whether sampling selects the nearest mip level (CL_FILTER_NEAREST) or performs trilinear interpolation between adjacent levels (CL_FILTER_LINEAR).
  • LOD Clamps: Sampler properties can enforce minimum and maximum LOD bounds (CL_SAMPLER_LOD_MIN and CL_SAMPLER_LOD_MAX), restricting sampling to a specific subset of the mip hierarchy.

When a kernel samples an image using a normalized coordinate, the hardware or software rasterizer calculates the rate of change of coordinates to automatically select the optimal mipmap level.

Extensions Exposing Mipmap Level Sampling

Standard OpenCL 1.x does not support mipmapping in core profiles. To address this, the Khronos Group introduced dedicated extensions that were later integrated into OpenCL 2.0 core specifications.

1. cl_khr_mipmap_image

The primary extension enabling mipmap functionality is cl_khr_mipmap_image. This extension exposes the capability to create, read, and query mipmapped 1D, 2D, and 3D images, as well as 1D and 2D image arrays.

Within OpenCL C kernels, this extension enables specialized built-in functions:

  • Explicit LOD Sampling: Kernels can override automatic level calculation by passing an explicit float lod parameter to the read_image functions (e.g., read_imagef(image, sampler, coord, lod)).
  • Gradient-Based Sampling: Kernels can supply explicit coordinate gradients (partial derivatives dx and dy) via functions like read_imagef(image, sampler, coord, dx, dy). This is essential for non-uniform flow control where automatic hardware derivation would fail or cause artifacts.
  • Level Queries: It exposes the get_image_num_mip_levels(image) built-in to query the total number of levels available in the texture chain directly from the kernel.

2. cl_khr_mipmap_image_writes

While cl_khr_mipmap_image provides read-only sampling capabilities, modifying specific mip levels from within a kernel requires the cl_khr_mipmap_image_writes extension.

This extension introduces variants of write_image functions that accept an integer lod argument (e.g., write_imagef(image, coord, lod, color)). This allows compute kernels to generate downsampled levels dynamically on the device without having to copy intermediate buffers back to the host.
