What Is the __global Address Space in OpenCL?

The __global address space qualifier in OpenCL designates that a memory object or pointer resides within the device’s global memory pool. This article provides a focused explanation of the __global qualifier, detailing its fundamental purpose in OpenCL kernel code, how it facilitates data exchange between the host and device, its visibility across computing units, and its architectural performance implications.

Primary Purpose of the __global Qualifier

OpenCL uses explicit memory qualifiers to map data directly to the underlying hardware hierarchy of a compute device (such as a GPU or multi-core CPU). The __global qualifier (or simply global) specifies that an allocated buffer resides in the main memory of the device.

The primary functions of the __global qualifier include:

  • Host-to-Device Data Sharing: Devices execute kernels on data supplied by the host application. Memory allocated via the OpenCL runtime on the host (e.g., using clCreateBuffer) lives in global memory. The __global keyword informs the compiler that a kernel argument points to these host-accessible memory allocations.
  • Universal Work-Item Visibility: Global memory is visible to all work-items across all work-groups executing the kernel. Any work-item can read from or write to any location in a global buffer, provided the buffer permissions allow it.
  • Persistent Execution State: Unlike private or local memory, which are allocated dynamically per thread or per work-group and cleared once execution completes, global memory persists across the execution of multiple consecutive kernels until explicitly released by the host.

Syntax and Kernel Arguments

Pointers passed as arguments to an OpenCL kernel must explicitly declare their address space. Because most input arrays and output buffers reside in the device's primary VRAM, __global is the most commonly used qualifier in kernel signatures.

__kernel void vector_add(__global const float *a,
                         __global const float *b,
                         __global float *result) {
    int id = get_global_id(0);
    result[id] = a[id] + b[id];
}

In the example above, __global tells the compiler that the pointers a, b, and result reference the high-capacity, off-chip global memory space rather than high-speed local scratchpad registers.

Performance and Synchronization Considerations

While __global memory provides the largest storage capacity on a compute device, it also has the highest access latency compared to __local (shared) or __private (register) memory. When using __global:

  • Memory Coalescing: For peak bandwidth, work-items within the same subgroup or warp should access consecutive memory locations in __global space. Non-contiguous or random access patterns significantly degrade memory throughput.
  • Caching: Depending on the hardware architecture, accesses to __global memory may pass through L1 and L2 hardware caches to mitigate latency.
  • Concurrency and Race Conditions: Because all work-items can access global memory simultaneously, concurrent writes to the same address result in race conditions. Developers must use atomic operations (such as atomic_add) or memory fences (CLK_GLOBAL_MEM_FENCE) to ensure proper synchronization across work-items.
