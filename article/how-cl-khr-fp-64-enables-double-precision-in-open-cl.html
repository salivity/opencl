How cl_khr_fp64 Enables Double Precision in OpenCL

The cl_khr_fp64 extension is the official Khronos Group specification used in OpenCL to indicate and enable 64-bit double-precision floating-point operations. Because double-precision arithmetic is not universally mandatory across all computing hardware, OpenCL uses this extension to let developers query hardware capabilities on the host side and safely compile double-precision arithmetic in kernel code.

The Purpose of cl_khr_fp64

Standard OpenCL specifications mandate single-precision (32-bit) floating-point calculations, but double-precision (64-bit) support depends heavily on the underlying GPU, CPU, or accelerator architecture. The cl_khr_fp64 extension acts as the bridge that signals native hardware support for IEEE 754-compliant 64-bit operations, including types like double, double2, double4, and corresponding mathematical built-in functions.

Querying Support on the Host

Before launching kernels that utilize 64-bit floats, the host application queries device capabilities using the OpenCL API function clGetDeviceInfo.

  1. Checking Device Extensions: Query the CL_DEVICE_EXTENSIONS parameter for the target device:

    size_t ext_size;
clGetDeviceInfo(device_id, CL_DEVICE_EXTENSIONS, 0, NULL, &ext_size);
char *extensions = (char *)malloc(ext_size);
clGetDeviceInfo(device_id, CL_DEVICE_EXTENSIONS, ext_size, extensions, NULL);

    If the returned space-delimited string contains cl_khr_fp64, the device hardware and its associated driver support 64-bit floating-point types.

  2. Checking Floating-Point Capabilities: Once cl_khr_fp64 is identified, the host can query specific hardware features by inspecting CL_DEVICE_DOUBLE_FP_CONFIG:

    cl_device_fp_config fp_config;
clGetDeviceInfo(device_id, CL_DEVICE_DOUBLE_FP_CONFIG, sizeof(cl_device_fp_config), &fp_config, NULL);

    This bitfield indicates specific hardware capabilities, including:

    • CL_FP_DENORM: Support for denormalized numbers.
    • CL_FP_INF_NAN: Support for INF and quiet NaNs.
    • CL_FP_ROUND_TO_NEAREST: Support for round-to-nearest-even mode.
    • CL_FP_ROUND_TO_ZERO: Support for round-to-zero mode.
    • CL_FP_ROUND_TO_INF: Support for round-to-positive/negative-infinity mode.
    • CL_FP_FMA: Support for fused multiply-add operations.

Enabling Double Precision in Kernel Code

Detecting the extension on the host ensures the hardware can run the code, but the OpenCL C compiler must also be instructed to parse 64-bit types. In the kernel source code, the extension is activated using a preprocessor pragma:

#pragma OPENCL EXTENSION cl_khr_fp64 : enable

__kernel void compute_double(__global const double *input, __global double *output) {
    int gid = get_global_id(0);
    output[gid] = input[gid] * 2.0;
}

If double-precision is optional within the kernel logic, conditional compilation directives can prevent compilation failures on unsupported devices:

#ifdef cl_khr_fp64
    #pragma OPENCL EXTENSION cl_khr_fp64 : enable
    typedef double real_t;
#else
    typedef float real_t;
#endif

Evolution Across OpenCL Versions

In OpenCL 1.0 and 1.1, double-precision capability was strictly available through cl_khr_fp64. Starting with OpenCL 1.2, double precision was shifted into an optional core feature. While modern OpenCL versions define the predefined macro FP_64 when double precision is available, drivers continue to expose cl_khr_fp64 in extension queries to maintain backward compatibility across heterogeneous systems.
