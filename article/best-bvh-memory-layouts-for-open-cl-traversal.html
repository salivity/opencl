Best BVH Memory Layouts for OpenCL Traversal

Optimizing Bounding Volume Hierarchy (BVH) traversal inside OpenCL kernels requires memory layouts tailored to the SIMT (Single Instruction, Multiple Threads) execution model of modern GPUs. Because ray traversal is inherently memory-bandwidth-bound and prone to divergent branching, standard pointer-based pointer-chasing structures cause severe performance bottlenecks. This article examines the most efficient memory configurations—including linear node flattening, Structure of Arrays (SoA) transformations, Wide BVH (BVH4/BVH8) packing, and node quantization—that ensure high cache utilization and memory coalescing in OpenCL.

Linearized Contiguous Buffers

Standard dynamic tree nodes linked by pointers must be flattened into continuous arrays inside OpenCL global memory (__global). Dynamic memory allocation is unsupported on device kernels, making index-based addressing the standard approach.

Arranging nodes in Depth-First Search (DFS) order—specifically layout variants like "left-child, right-sibling"—guarantees spatial locality during traversal. In a typical DFS layout, the near child immediately follows the parent node in memory. If a ray intersects a parent node, loading the next child often results in an L1/L2 cache hit because the data resides on the same or adjacent cache lines.

Structure of Arrays (SoA) and Hybrid AoSoA

Using a standard Array of Structures (AoS) format, such as:

struct BVHNode {
    float3 bbox_min;
    float3 bbox_max;
    int left_child;
    int right_child;
};

wastes memory bandwidth. When multiple work-items within a wavefront or warp evaluate different tree levels or coordinate axes simultaneously, AoS produces strided, non-coalesced global memory reads.

A Structure of Arrays (SoA) approach divides node attributes into separate global buffers:

  • __global float* bboxes_min_x;
  • __global float* bboxes_min_y;
  • __global float* bboxes_min_z;
  • __global float* bboxes_max_x;
  • __global float* bboxes_max_y;
  • __global float* bboxes_max_z;
  • __global int2* children_indices;

When threads in a wavefront evaluate the same bounding box components, SoA ensures adjacent threads access contiguous memory addresses, leading to fully coalesced 128-byte transactions. Alternatively, an Array of Structures of Arrays (AoSoA) packs groups of 4 or 8 nodes into vector types (such as OpenCL's native float4 or float8), matching the hardware's SIMD lanes while preserving hierarchical locality.

Wide BVH (BVH4 and BVH8) Layouts

Binary BVHs (BVH2) feature deeper hierarchies, increasing the number of global memory roundtrips per ray. Wide BVHs, such as BVH4 (quad-tree) or BVH8 (oct-tree), collapse multiple binary levels into a single wider node.

In a BVH4 configuration, each internal node contains the bounding boxes of four children. This mapping aligns with OpenCL vector types:

  • Node bounds can be represented as six float4 values (three for minima: min_x, min_y, min_z, and three for maxima: max_x, max_y, max_z).
  • A single work-item tests a ray against all four child boxes using vectorized arithmetic (fmin, fmax), reducing the total number of node fetch instructions and tree traversal depth by up to 50%.

Cache-Aligned 32-Byte and 64-Byte Node Packing

GPU memory controllers fetch data in 32-byte, 64-byte, or 128-byte segments. BVH nodes should be explicitly sized to powers of two to prevent individual nodes from straddling two cache lines.

For binary trees, a compact 32-byte layout can be achieved:

  • Child pointer / Leaf index (4 bytes): A signed integer where positive values represent an offset to the first child and negative values represent primitive indices.
  • Axis / Metadata (4 bytes): Split axis and primitive count packed into bitfields.
  • Bounding Boxes (24 bytes): Reduced representation using single-precision coordinate pairs.

Aligning nodes with the __attribute__((aligned(32))) or __attribute__((aligned(64))) qualifiers ensures every fetch maps directly to a single memory transaction without redundant transfers.

Compressed Wide BVH (CWBVH)

For memory-constrained scenes, Compressed Wide BVH reduces memory footprint and maximizes cache residency. In this format:

  1. The global scene bounds are stored at high precision.
  2. Individual child bounding boxes inside an 8-wide node (BVH8) are quantized into 8-bit integers relative to the parent bounding box.
  3. Quantization scales down node sizes from 120+ bytes to just 64 or 80 bytes per wide node.

By decompressing bounds on-chip using fast arithmetic operations (such as multiply-add), bandwidth pressure shifts to computational units, yielding significant speedups on modern GPU architectures.

Traversal Memory Considerations: Private vs. Local Memory

The efficiency of a memory layout depends directly on the traversal stack implementation:

  • Private Memory Stacks: Placing the node index traversal stack in private memory maps it to hardware registers. If register pressure causes spilling, the stack spills to slow local or global scratchpad memory.
  • Stackless Traversal: Layouts modified with parent pointers, escape indices (skip-pointers), or bit-trails remove the need for an in-memory stack entirely, reducing node footprint and eliminating register spills at the expense of redundant ray-box evaluations.
