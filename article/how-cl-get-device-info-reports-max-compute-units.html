How clGetDeviceInfo Reports Max Compute Units

This article explains how the OpenCL API queries and reports the maximum compute units available on a target hardware device using the clGetDeviceInfo function. It details the specific query parameter required, the underlying data type returned, how hardware vendors map their physical architectures to OpenCL compute units, and includes a practical code example illustrating the query implementation.

The Query Mechanism

To determine the number of compute units on an OpenCL device, the host application calls clGetDeviceInfo using the CL_DEVICE_MAX_COMPUTE_UNITS flag for the param_name argument.

The function signature is defined as follows:

cl_int clGetDeviceInfo(
    cl_device_id device,
    cl_device_info param_name,
    size_t param_value_size,
    void *param_value,
    size_t *param_value_size_ret
);

When passing CL_DEVICE_MAX_COMPUTE_UNITS:

  • Return Type: The query returns a cl_uint, which is a 32-bit unsigned integer.
  • Buffer Size: param_value_size must be at least sizeof(cl_uint).
  • Value Meaning: The returned integer represents the core execution units present on the device capable of processing work-groups in parallel.

Implementation Example

The following C snippet demonstrates how to query and print the compute units for a valid device_id:

#include <CL/cl.h>
#include <stdio.h>

void print_max_compute_units(cl_device_id device) {
    cl_uint compute_units;
    cl_int err = clGetDeviceInfo(
        device,
        CL_DEVICE_MAX_COMPUTE_UNITS,
        sizeof(cl_uint),
        &compute_units,
        NULL
    );

    if (err == CL_SUCCESS) {
        printf("Max Compute Units: %u\n", compute_units);
    } else {
        printf("Failed to query device info. Error code: %d\n", err);
    }
}

Architectural Mapping Across Vendors

The term "compute unit" is an abstract OpenCL concept. The OpenCL runtime driver provided by the hardware vendor translates the physical hardware architecture into this metric:

  • NVIDIA GPUs: A compute unit maps directly to a Streaming Multiprocessor (SM). Each SM contains multiple CUDA cores (ALUs), but clGetDeviceInfo reports the total SM count, not individual CUDA cores.
  • AMD GPUs: A compute unit maps to a physical Compute Unit (CU) or Dual Compute Unit (WGP - Workgroup Processor) depending on the architecture (GCN or RDNA). Each CU contains multiple SIMD vector units.
  • CPUs: A compute unit typically maps to a single CPU core (or logical thread if simultaneous multithreading/hyper-threading is enabled and recognized by the runtime).
  • Intel Integrated GPUs: A compute unit generally maps to an Execution Unit (EU) subslice or Xe-core, depending on the generation.

Performance Considerations

The value returned by CL_DEVICE_MAX_COMPUTE_UNITS defines the hardware parallelism limit for work-groups. Because one OpenCL work-group executes concurrently on a single compute unit, the reported count indicates how many work-groups can actively execute in hardware at the exact same time without scheduling latency. It serves as a primary metric for determining global and local work sizes to ensure the device remains fully saturated.
