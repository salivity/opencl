OpenCL Normalized Coordinate Modes for Images

This article provides an overview of normalized coordinate handling in OpenCL image sampling, detailing how normalized coordinates function, how they are configured within samplers, and which addressing modes are supported when utilizing normalized coordinate spaces.

In OpenCL, image read functions can sample textures and images using either unnormalized coordinates or normalized coordinates. This behavior is defined when creating a sampler object (cl_sampler via the OpenCL API or sampler_t directly within OpenCL C kernel code) using the normalized coordinates flag.

The Normalized Coordinate States

OpenCL supports two primary modes for image coordinate interpretation:

  • Normalized Coordinates Enabled (CLK_NORMALIZED_COORDS_TRUE / CL_TRUE): Coordinate values are specified as floating-point numbers ranging from 0.0 to 1.0, where 0.0 represents the edge of the first pixel and 1.0 represents the edge of the last pixel, independent of the underlying image dimensions.
  • Unnormalized Coordinates Enabled (CLK_NORMALIZED_COORDS_FALSE / CL_FALSE): Coordinates are interpreted directly in pixel/element units ranging from 0 to the image's dimension minus one (width - 1, height - 1, etc.).

Addressing Modes Supported with Normalized Coordinates

When normalized coordinates are set to CLK_NORMALIZED_COORDS_TRUE, OpenCL specifies how out-of-bounds coordinates (values less than 0.0 or greater than 1.0) are processed via addressing modes. The following addressing modes are supported:

  • CLK_ADDRESS_REPEAT (or CL_ADDRESS_REPEAT): Out-of-bounds coordinates wrap around periodically. This mode is exclusively supported with normalized coordinates and cannot be used with unnormalized coordinates. A coordinate of 1.2 maps to 0.2.
  • CLK_ADDRESS_MIRRORED_REPEAT (or CL_ADDRESS_MIRRORED_REPEAT): Out-of-bounds coordinates reflect at the boundaries, effectively mirroring the texture across the [0.0, 1.0] range. This mode is also designed strictly for normalized coordinates.
  • CLK_ADDRESS_CLAMP_TO_EDGE (or CL_ADDRESS_CLAMP_TO_EDGE): Coordinates falling outside [0.0, 1.0] are clamped to the boundary pixels: values below 0.0 clamp to the nearest valid edge coordinate, and values above 1.0 clamp to the opposing edge.
  • CLK_ADDRESS_CLAMP (or CL_ADDRESS_CLAMP): Coordinates outside the [0.0, 1.0] range return a predefined border color (either (0.0, 0.0, 0.0, 0.0) for float formats or (0, 0, 0, 0) for integer formats).
  • CLK_ADDRESS_NONE (or CL_ADDRESS_NONE): Out-of-bounds behavior is undefined. This option bypasses hardware boundary checking to maximize read performance when coordinates are guaranteed to fall strictly within the [0.0, 1.0] range.

Filtering Interaction

Normalized coordinates function across both supported filtering modes:

  • CLK_FILTER_NEAREST: Samples the single pixel closest to the normalized coordinate.
  • CLK_FILTER_LINEAR: Performs linear interpolation (bilinear for 2D, trilinear for 3D) across neighboring pixels based on the normalized floating-point position.
