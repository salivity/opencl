OpenCL Samplers: Texture Addressing and Linear Filtering

OpenCL sampler objects define how an OpenCL device reads image data by configuring coordinate normalization, addressing modes, and filtering behaviors. When a kernel reads an image using built-in read functions, the associated sampler specifies how coordinates outside the image boundaries are resolved and how discrete pixels are interpolated to produce the final color or vector value.

Structure of an OpenCL Sampler

A sampler can be defined in the host code using the OpenCL API (such as clCreateSamplerWithProperties) or declared directly within OpenCL C kernel code using the sampler_t type. A sampler is configured with three primary properties:

  1. Normalized Coordinates: Determines whether coordinate values fall within the range [0.0, 1.0] or map directly to absolute pixel dimensions [0, image_width] and [0, image_height].
  2. Addressing Mode: Dictates how out-of-bounds coordinates are handled.
  3. Filter Mode: Dictates how values are interpolated between discrete texels.

Controlling Texture Addressing Modes

Texture addressing controls the pixel color returned when a kernel samples an image using coordinates that fall outside the defined boundaries. OpenCL supports five distinct addressing modes:

  • CLK_ADDRESS_CLAMP_TO_EDGE: Out-of-range coordinates are clamped to the extent of the image. Any read beyond the border evaluates to the color of the nearest edge pixel.
  • CLK_ADDRESS_CLAMP: Coordinates outside the range return a designated border color, which evaluates to (0.0, 0.0, 0.0, 0.0) for images with float or half data types, or (0, 0, 0, 1) where applicable for specific integer formats.
  • CLK_ADDRESS_REPEAT: Coordinates wrap cyclically across the image. This mode can only be used when normalized coordinates are set to true. For example, a coordinate of 1.25 wraps around to 0.25.
  • CLK_ADDRESS_MIRRORED_REPEAT: Coordinates mirror back and forth across the image boundaries at every integer boundary. Like the repeat mode, this requires normalized coordinates.
  • CLK_ADDRESS_NONE: Out-of-bounds behavior is undefined. This option bypasses hardware boundary checks, offering the highest performance when memory accesses are guaranteed to remain within valid bounds.

Linear Filtering Behavior

The filter mode controls how OpenCL reconstructs continuous image data from discrete texels. OpenCL provides two primary filter modes: CLK_FILTER_NEAREST and CLK_FILTER_LINEAR.

When CLK_FILTER_NEAREST is used, the hardware performs point sampling, returning the pixel whose center is closest to the provided coordinate. This approach is fast but results in blocky artifacts when an image is magnified.

When CLK_FILTER_LINEAR is enabled, the sampler performs bilinear (for 2D images) or trilinear (for 3D images) interpolation:

  • Sampling Grid: For a 2D coordinate \((u, v)\), the hardware identifies the four nearest pixel centers bounding the target coordinate.
  • Weights Calculation: The fractional component of the coordinate determines the interpolation weights: \[\alpha = u - \lfloor u - 0.5 \rfloor - 0.5\] \[\beta = v - \lfloor v - 0.5 \rfloor - 0.5\]
  • Interpolation: The hardware computes a weighted average of the four surrounding texels (\(T_{00}, T_{10}, T_{01}, T_{11}\)): \[T = (1 - \alpha)(1 - \beta)T_{00} + \alpha(1 - \beta)T_{10} + (1 - \alpha)\beta T_{01} + \alpha\beta T_{11}\]

Linear filtering is supported primarily on normalized floating-point and unnormalized half/float image formats. If linear filtering is applied to integer-based formats (such as signed or unsigned integer images), the OpenCL specification dictates that the read operation defaults to nearest-neighbor sampling.
