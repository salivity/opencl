OpenCL Sub-Group Broadcast Functions

Sub-group operations in modern OpenCL standards allow work-items within the same hardware execution unit (such as a wavefront or warp) to communicate directly without using local memory or synchronization barriers. In OpenCL 2.1 and OpenCL 3.0, the primary built-in function designed specifically for sharing data across an entire sub-group from a single work-item is sub_group_broadcast. This article details the syntax, behavior, and supported extensions for broadcasting data across sub-groups in recent OpenCL versions.

The sub_group_broadcast Built-In Function

The dedicated function for broadcasting values across a sub-group is sub_group_broadcast. It reads a value from a designated work-item within the sub-group and shares it with all other work-items in that same sub-group.

The function signature follows this general pattern:

T sub_group_broadcast(T x, uint sub_group_local_id);
  • x: The value to be broadcast. While every work-item supplies an argument to x, only the value from the work-item whose local ID matches sub_group_local_id is used.
  • sub_group_local_id: The index (ranging from 0 to get_sub_group_size() - 1) of the work-item within the sub-group that provides the value. This value must be identical for all work-items executing the operation within the sub-group (a uniform value).
  • Return Value: The value of x originating from the specified work-item.

Supported Data Types

In core OpenCL 2.1 and OpenCL 3.0 (with the __opencl_c_subgroups feature macro enabled), sub_group_broadcast natively supports standard 32-bit scalar data types:

  • 32-bit signed and unsigned integers (int, uint)
  • Single-precision floating-point numbers (float)
  • Pointer types (void*, generic pointers)

Support for broader data types is made available through official OpenCL extensions:

  • cl_khr_subgroup_extended_types: Adds support for 8-bit integers (char, uchar), 16-bit integers (short, ushort), 64-bit integers (long, ulong), and vector variations (such as float4, int2).
  • cl_khr_fp16: Enables broadcasting for half-precision floating-point types (half).
  • cl_khr_fp64: Enables broadcasting for double-precision floating-point types (double).

Related Shuffle Functions as Flexible Broadcasts

While sub_group_broadcast requires a uniform origin across all work-items, the cl_khr_subgroup_shuffle and cl_khr_subgroup_shuffle_relative extensions provide dynamic broadcast mechanisms:

  • sub_group_shuffle(T x, uint current_id): Allows arbitrary permutations of data. If all work-items pass the same current_id, it behaves identically to a broadcast, but it also allows different work-items to pull from different IDs simultaneously.
  • sub_group_shuffle_down(T current, T next, uint delta) and sub_group_shuffle_up(T previous, T current, uint delta): Allow relative lane transfers, functioning as specialized relative broadcasts across subsets of a sub-group.

Availability and Version Requirements

The sub_group_broadcast function was initially defined in the cl_khr_subgroups extension before being integrated into the core OpenCL 2.1 standard. In OpenCL 3.0, sub-group support became optional; devices indicate support through the CL_DEVICE_SUB_GROUP_INDEPENDENT_FORWARD_PROGRESS property and OpenCL C compiler macros (__opencl_c_subgroups). Ensure your target device supports either OpenCL 2.1+, the __opencl_c_subgroups feature, or the cl_khr_subgroups extension prior to deploying sub-group broadcast operations.
