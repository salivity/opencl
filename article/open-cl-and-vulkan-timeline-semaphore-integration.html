OpenCL and Vulkan Timeline Semaphore Integration

This article explores how OpenCL semaphore extensions bridge the gap between OpenCL compute operations and Vulkan graphics pipelines using external timeline semaphores. It details the limitations of legacy synchronization methods, explains the mechanics of timeline-based signaling within OpenCL, and highlights the performance benefits of direct, non-blocking GPU-to-GPU task coordination.

Historically, sharing resources between OpenCL and Vulkan required coarse-grained, host-mediated synchronization. Applications typically had to stall the host CPU using barriers, flushes, or synchronization constructs like clWaitForEvents and vkWaitForFences. This round-trip communication across the PCIe bus introduced significant latency, degraded pipeline throughput, and underutilized modern GPU scheduling capabilities.

The introduction of extensions such as cl_khr_semaphore and cl_khr_external_semaphore resolves these bottlenecks. These extensions allow an OpenCL context to import native OS handles—such as POSIX file descriptors or Windows NT handles—associated with external Vulkan timeline semaphores (VkSemaphore configured with VK_SEMAPHORE_TYPE_TIMELINE). Once imported, the external timeline semaphore is encapsulated as a native cl_semaphore_khr object.

Unlike binary semaphores, which exist strictly in an unsignaled or signaled state, timeline semaphores operate on a monotonically increasing 64-bit unsigned integer value. This distinct state model enables fine-grained, out-of-order, and many-to-many dependency graphs. An application can enqueue work that waits for a specific counter value and subsequently signals an incremented value upon completion.

Within an OpenCL command queue, synchronization is managed directly via GPU hardware using commands like clEnqueueWaitSemaphoresKHR and clEnqueueSignalSemaphoresKHR. When an OpenCL kernel is queued, it can be instructed to wait until the Vulkan pipeline writes a specific value to the shared timeline semaphore. As soon as the condition is satisfied, the GPU hardware scheduler begins the OpenCL kernel execution without CPU involvement. After completing its computation, the OpenCL kernel updates the timeline semaphore to a target value, immediately unblocking downstream Vulkan commands configured to wait on that updated value.

By shifting cross-API synchronization directly to the GPU scheduler, these semaphore extensions eliminate host-side coordination overhead. This enables seamless, low-latency interoperability for complex pipelines, such as rendering a scene in Vulkan, post-processing or running physics calculations on that scene in OpenCL, and returning the output to the Vulkan presentation queue.
