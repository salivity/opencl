Role of PCIe ATS in Full OpenCL SVM Operation

This article explores how Peripheral Component Interconnect Express (PCIe) Address Translation Services (ATS) enable full OpenCL Shared Virtual Memory (SVM). It examines the mechanics of Fine-Grained System SVM, details how ATS coordinates translation requests between discrete accelerators and host memory management units, and explains why this hardware mechanism is critical for unified pointer sharing, low-latency execution, and seamless heterogeneous computing.

OpenCL Shared Virtual Memory Levels

OpenCL defines three tiers of Shared Virtual Memory: Coarse-Grained Buffer SVM, Fine-Grained Buffer SVM, and Fine-Grained System SVM.

While Coarse-Grained and Fine-Grained Buffer modes require explicitly allocated OpenCL buffers, Fine-Grained System SVM represents "full" SVM. In this mode, the host CPU and the compute device share the entire virtual address space. Complex, pointer-rich data structures (such as linked lists, graphs, and trees) allocated via standard host memory allocators (like malloc or new) can be passed directly to the device kernel without marshaling, pointer offsets, or explicit data transfers.

The Memory Translation Challenge in PCIe Devices

For a discrete device (such as a GPU or FPGA) to access host system memory, it must operate across the PCIe bus. Historically, devices either operated using physical memory addresses or accessed virtual memory mediated entirely through an I/O Memory Management Unit (IOMMU).

Full OpenCL SVM requires the device to resolve the exact same virtual addresses that the host CPU uses. If every memory read or write by the device required a round-trip PCIe transaction to the host IOMMU to resolve page tables, device memory access would suffer extreme latency penalties, rendering Fine-Grained System SVM impractical.

How PCIe Address Translation Services (ATS) Works

PCIe Address Translation Services solves this bottleneck by decentralizing virtual-to-physical address translation. ATS introduces a client-server architecture between the PCIe endpoint (the accelerator) and the root complex (the host IOMMU):

  1. Address Translation Cache (ATC): The PCIe device contains an internal cache of page translations, analogous to a CPU Translation Lookaside Buffer (TLB).
  2. Translation Request and Completion: When the device encounters a host virtual address missing from its ATC, it sends a PCIe Translation Request to the host IOMMU. The host IOMMU consults the CPU page tables and returns a Translation Completion packet containing the physical address and access permissions.
  3. Local Caching: The device stores this mapping in its ATC, allowing subsequent memory operations to that page to proceed with native-like throughput without host-side translation overhead.
  4. Invalidation Protocol: When the host operating system unmaps, swaps, or relocates a page, the IOMMU transmits an ATS Invalidation Request across the PCIe link. The device purges the mapping from its ATC and acknowledges the invalidation, ensuring strict memory consistency between host and device.

Integration with the Page Request Interface (PRI)

ATS is frequently paired with the PCIe Page Request Interface (PRI) to support demand paging—a critical requirement for robust Fine-Grained System SVM. If an accelerator accesses a virtual address that has not yet been committed to physical RAM by the host OS (a page fault), the device cannot complete the access immediately.

Through PRI, the device sends a Page Request message across PCIe, asking the host OS to allocate physical memory and update the page tables. Once the host resolves the fault, it responds via ATS, enabling the device to resume execution. This eliminates the need to pin the entire host virtual memory space before launching compute kernels.

Summary of the Role of ATS in Full OpenCL SVM

Without PCIe ATS, full OpenCL SVM would be limited to architectures with physically unified, coherent memory buses (such as integrated system-on-chip designs). ATS extends these capabilities to discrete accelerators by:

  • Providing a standardized, hardware-level protocol for synchronizing device-side ATCs with host-side MMU page tables.
  • Eliminating per-access IOMMU lookups, achieving low-latency access to standard host-allocated pointers.
  • Enabling unified virtual addressing across heterogeneous components while maintaining page-level security, memory protection, and page eviction capabilities.
