Containerizing OpenCL with Docker Device Pass-Through

Containerizing OpenCL compute jobs allows developers to package complex scientific, machine learning, and image-processing workloads into reproducible environments while maintaining bare-metal execution speeds. Achieving this requires exposing the host's underlying hardware interfaces to the Docker container and configuring the user-space Installable Client Driver (ICD) runtime. This guide explains how to properly configure Docker device flags, set up vendor-specific user-space drivers, and ensure zero-overhead hardware pass-through for Intel, AMD, and NVIDIA accelerators.

Prerequisites on the Host System

Before configuring Docker, the host system must have the appropriate kernel modules and hardware drivers operational. The host must already be capable of executing OpenCL workloads natively.

  1. Ensure the GPU or accelerator is recognized by the kernel: 
    lspci | grep -i -E "vga|3d|display|compute"
  2. Verify that native OpenCL device query utilities like clinfo report your hardware properly on the host before attempting containerization.

Passing Hardware Device Nodes

Docker isolates containers from the host hardware by default. To pass the necessary hardware devices without running the container in insecure --privileged mode, use specific --device flags corresponding to the accelerator architecture.

Intel GPUs (Intel Graphics Compute Runtime / NEO)

Intel integrated and discrete GPUs expose their interfaces via the Direct Rendering Manager (DRM).

Pass the render and card nodes:

docker run --rm \
  --device /dev/dri:/dev/dri \
  --group-add video \
  --group-add render \
  opencl-intel-image clinfo

AMD GPUs (ROCm / PAL)

AMD devices utilize both the Kernel Fusion Driver (/dev/kfd) for compute and the DRM render nodes for memory and display subsystems.

Pass both nodes along with appropriate group permissions:

docker run --rm \
  --device /dev/kfd \
  --device /dev/dri \
  --group-add video \
  --group-add render \
  opencl-amd-image clinfo

NVIDIA GPUs

NVIDIA compute relies on the NVIDIA Container Toolkit instead of standard /dev/dri nodes. The toolkit dynamically injects host driver libraries and device files into the container.

Run with the NVIDIA runtime enabled:

docker run --rm \
  --gpus all \
  opencl-nvidia-image clinfo

Constructing the Container Environment

Passing device nodes provides hardware access, but the container must contain the user-space OpenCL runtime and the OpenCL Installable Client Driver (ICD) loader to interface with the kernel modules.

Dockerfile for Intel OpenCL

For modern Intel processors (Broadwell and newer), use the Intel NEO open-source compute runtime:

FROM ubuntu:22.04

ENV DEBIAN_FRONTEND=noninteractive

RUN apt-get update && apt-get install -y \
    ocl-icd-libopencl1 \
    opencl-headers \
    clinfo \
    intel-opencl-icd \
    && rm -rf /var/lib/apt/lists/*

CMD ["clinfo"]

Dockerfile for AMD ROCm OpenCL

For AMD Radeon or Instinct hardware, integrate the official ROCm repositories or runtime packages:

FROM ubuntu:22.04

ENV DEBIAN_FRONTEND=noninteractive

RUN apt-get update && apt-get install -y \
    wget \
    gnupg2 \
    ca-certificates \
    ocl-icd-libopencl1 \
    clinfo

# Install AMD ROCm OpenCL runtime
RUN wget -qO - https://repo.radeon.com/rocm/rocm.gpg.key | apt-key add - && \
    echo 'deb [arch=amd64] https://repo.radeon.com/rocm/apt/debian/ ubuntu main' | tee /etc/apt/sources.list.d/rocm.list && \
    apt-get update && apt-get install -y \
    rocm-opencl-runtime && \
    rm -rf /var/lib/apt/lists/*

CMD ["clinfo"]

Dockerfile for NVIDIA OpenCL

NVIDIA images should use the official CUDA base image, which configures the ICD entries automatically:

FROM nvidia/cuda:12.2.0-base-ubuntu22.04

RUN apt-get update && apt-get install -y \
    ocl-icd-libopencl1 \
    opencl-headers \
    clinfo \
    && rm -rf /var/lib/apt/lists/*

# Point the OpenCL ICD loader to the injected NVIDIA library
RUN mkdir -p /etc/OpenCL/vendors && \
    echo "libnvidia-opencl.so.1" > /etc/OpenCL/vendors/nvidia.icd

CMD ["clinfo"]

Managing Device Permissions

A common failure mode in containerized OpenCL jobs is a permission denied error when accessing /dev/dri/renderD* or /dev/kfd.

  • Inspect the group IDs on the host: 
    ls -l /dev/dri/renderD*
ls -l /dev/kfd
  • Typically, these belong to the render (GID often 110 or 107) and video (GID 44) groups.
  • Map these groups into the container execution by supplying --group-add <host_group_id> or --group-add render in your execution commands.

Verifying Deployment

Verify successful integration by executing clinfo inside the running container. The output should display the exact platform name, OpenCL C version, and target device (e.g., Intel(R) Graphics, AMD Radeon Graphics, or NVIDIA CUDA) matching the host machine. If clinfo returns Number of platforms: 0, verify that the device files exist inside the container using docker run <flags> <image> ls -la /dev/dri and that the /etc/OpenCL/vendors/*.icd file is properly installed.
