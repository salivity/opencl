Units for OpenCL Profiling Timer Measurements

This article explains the standard units used to express profiling timer tick measurements in OpenCL. It covers how OpenCL captures command queue performance data, how developers query timestamps, and the specific time scale used to calculate kernel execution and data transfer durations.

In OpenCL, profiling timer tick measurements are universally expressed in nanoseconds (ns). Whenever profiling is enabled on an OpenCL command queue, the OpenCL runtime records internal device timestamps as 64-bit unsigned integer values (cl_ulong), where each tick increment corresponds directly to one nanosecond of elapsed time.

How OpenCL Measures Profiling Ticks

Profiling is activated by passing the CL_QUEUE_PROFILING_ENABLE flag when creating the command queue using clCreateCommandQueueWithProperties (or clCreateCommandQueue in older OpenCL versions). Once enabled, developers can query timestamps using the clGetEventProfilingInfo function associated with an event.

OpenCL provides four key profiling points, all returned as 64-bit values in nanoseconds:

  • CL_PROFILING_COMMAND_QUEUED: The time when the command was enqueued by the host.
  • CL_PROFILING_COMMAND_SUBMIT: The time when the command was submitted by the host to the target device.
  • CL_PROFILING_COMMAND_START: The time when the command began executing on the device.
  • CL_PROFILING_COMMAND_END: The time when the command finished execution on the device.

Calculating Execution Time

Because the timestamps represent absolute time points from an arbitrary platform-dependent epoch, you determine duration by subtracting the start timestamp from the end timestamp.

The resulting difference is in nanoseconds:

\[\text{Elapsed Nanoseconds} = \text{CL\_PROFILING\_COMMAND\_END} - \text{CL\_PROFILING\_COMMAND\_START}\]

To convert this value into more common profiling units:

  • Divide by \(1,000,000.0\) to get milliseconds (\(\text{ms}\)).
  • Divide by \(1,000,000,000.0\) to get seconds (\(\text{s}\)).

Profiling Timer Resolution

Although the units are defined in nanoseconds, hardware timers may not tick with single-nanosecond precision. To check the actual resolution of the device's counter, query clGetDeviceInfo using the CL_DEVICE_PROFILING_TIMER_RESOLUTION flag. This query returns a size_t value that also specifies the timer resolution directly in nanoseconds.
