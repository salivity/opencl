Coarse-Grained vs Fine-Grained SVM in OpenCL

Shared Virtual Memory (SVM) in OpenCL allows the host (CPU) and device (such as a GPU) to share a single, unified virtual address space, eliminating the need to manually copy pointer-rich data structures back and forth. The primary difference between coarse-grained and fine-grained SVM lies in the level of synchronization, memory coherency, and access granularity supported by the hardware and the runtime. While coarse-grained SVM requires explicit synchronization at the buffer level, fine-grained SVM allows concurrent, byte-level access and updates between the host and device.

Coarse-Grained SVM

Coarse-grained SVM operates at the buffer boundary level. In this model, the host and device can share virtual addresses, meaning complex data structures like linked lists or trees can be traversed directly using pointers without serializing the data. However, concurrent access to the same memory region is strictly prohibited during kernel execution.

Key characteristics include:

  • Explicit Synchronization: Developers must use explicit map and unmap commands (such as clEnqueueSVMMap and clEnqueueSVMUnmap) to transfer ownership of the memory region between the host and the OpenCL device.
  • Buffer-Level Granularity: Updates are only synchronized at the boundaries of the mapped regions when unmapped, rather than dynamically as writes occur.
  • Hardware Support: It has minimal hardware requirements and is supported on virtually all OpenCL 2.0+ compliant devices, as it does not rely on hardware-level cache coherency between the host CPU and the compute device.

Fine-Grained SVM

Fine-grained SVM provides a much closer integration between the host and device memory systems by enabling byte-level or variable-level memory sharing. This allows both the host CPU and the OpenCL device to read and write to the same virtual memory buffer simultaneously without requiring explicit map and unmap operations.

Key characteristics include:

  • Implicit Synchronization: Individual memory updates can be visible across both the host and device without mapping operations. Memory consistency is maintained either through standard memory consistency protocols or OpenCL 2.0 atomic operations.
  • Concurrent Access: The host and the device can read and modify overlapping memory regions concurrently during execution.
  • Hardware Requirements: It requires more advanced hardware support, specifically cache coherency between the host processor and the OpenCL device caches.

Key Differences Summary

  • Access Synchronization: Coarse-grained requires explicit map/unmap API calls to establish memory consistency. Fine-grained handles consistency implicitly or via atomic operations.
  • Concurrency: Coarse-grained forbids concurrent access to the same buffer by host and device. Fine-grained allows concurrent access down to individual bytes or memory words.
  • Performance Trade-offs: Coarse-grained has lower hardware overhead and predictable transfer boundaries, making it ideal for bulk transfers. Fine-grained enables lower latency and simplified code for dynamic workloads and interactive pointer chasing, but it relies heavily on cache-coherent interconnects.
