Implementing FDK Algorithm in OpenCL

This article provides a technical guide on implementing the Feldkamp-Davis-Kress (FDK) algorithm for cone-beam computed tomography (CBCT) reconstruction using OpenCL. It covers the core mathematical stages of the algorithm—cosine pre-weighting, 1D ramp filtering, and voxel-driven 3D backprojection—while detailing how to leverage OpenCL kernels, hardware interpolation via image samplers, and memory management techniques to achieve high-performance reconstruction on heterogeneous hardware.

1. Understanding the FDK Pipeline

The FDK algorithm is an analytical filtered backprojection (FBP) method designed for circular cone-beam trajectories. The pipeline consists of three sequential operations:

  1. Pre-weighting: Applying a geometry-dependent cosine weighting factor to each projection pixel to correct for cone-beam divergence.
  2. Filtering: Convolving each horizontal detector row with a 1D ramp filter (such as a Ram-Lak or Shepp-Logan filter) to handle frequency-domain sampling density.
  3. Backprojection: Projecting the filtered data back into a 3D Cartesian volume using a voxel-driven approach with a distance-squared scaling factor.

2. Pre-Weighting Kernel

In a flat-panel CBCT geometry, rays striking the detector at an angle travel farther than central rays. The pre-weighting factor compensates for this path-length difference:

\[w(u, v) = \frac{D}{\sqrt{D^2 + u^2 + v^2}}\]

where \(D\) is the source-to-isocenter distance, and \(u\) and \(v\) are physical coordinates on the detector plane relative to the principal point.

In OpenCL, this is implemented as a 2D kernel executing over the dimensions of the projection:

__kernel void fdk_preweight(
    __global float* projection,
    const int width,
    const int height,
    const float source_to_detector,
    const float pixel_size_u,
    const float pixel_size_v,
    const float u_offset,
    const float v_offset)
{
    int gx = get_global_id(0);
    int gy = get_global_id(1);

    if (gx >= width || gy >= height) return;

    float u = (gx - u_offset) * pixel_size_u;
    float v = (gy - v_offset) * pixel_size_v;
    float weight = source_to_detector / sqrt(source_to_detector * source_to_detector + u * u + v * v);

    int idx = gy * width + gx;
    projection[idx] *= weight;
}

3. Row-Wise 1D Ramp Filtering

Each horizontal row of the weighted projection must be filtered independently in the frequency domain.

  1. Fast Fourier Transform (FFT): Compute the 1D forward FFT of each row. The OpenCL library clFFT can batch 1D transforms across all detector rows efficiently.
  2. Spectral Multiplication: Multiply the transformed rows by the frequency response of a discretized ramp filter (e.g., \(|f|\) attenuated by a window function).
  3. Inverse FFT: Apply the 1D inverse FFT to return the projection to the spatial domain.

Pad the detector width to the next power of two prior to filtering to eliminate circular convolution artifacts.

4. Voxel-Driven Backprojection Kernel

The backprojection stage represents over 90% of the total computation. A voxel-driven approach maps one OpenCL work-item to each voxel in the output 3D volume \((X, Y, Z)\), allowing massive parallelization without write-conflict hazards.

Utilizing Hardware Texture Samplers

By binding the filtered 2D projections to OpenCL image2d_t objects, the GPU's fixed-function texture hardware handles bilinear interpolation automatically, avoiding manual floating-point interpolation in software.

__constant sampler_t sampler = CLK_NORMALIZED_COORDS_FALSE | 
                              CLK_ADDRESS_CLAMP_TO_EDGE | 
                              CLK_FILTER_LINEAR;

__kernel void fdk_backproject(
    __read_only image2d_t projection,
    __global float* volume,
    const float angle_rad,
    const float source_to_isocenter,
    const float source_to_detector,
    const int dim_x, const int dim_y, const int dim_z,
    const float voxel_size,
    const float u_mid, const float v_mid,
    const float inv_pixel_size)
{
    int x = get_global_id(0);
    int y = get_global_id(1);
    int z = get_global_id(2);

    if (x >= dim_x || y >= dim_y || z >= dim_z) return;

    // Physical voxel position relative to rotation axis
    float px = (x - dim_x * 0.5f) * voxel_size;
    float py = (y - dim_y * 0.5f) * voxel_size;
    float pz = (z - dim_z * 0.5f) * voxel_size;

    // Rotate voxel into the current projection's coordinate frame
    float cos_a = cos(angle_rad);
    float sin_a = sin(angle_rad);
    float s_rot = px * cos_a + py * sin_a;
    float t_rot = -px * sin_a + py * cos_a;

    // Distance from source to the rotated voxel along the principal ray
    float d_source = source_to_isocenter - t_rot;

    if (d_source > 0.0f) {
        // Perspective projection to detector coordinates
        float factor = source_to_detector / d_source;
        float u_proj = (s_rot * factor) * inv_pixel_size + u_mid;
        float v_proj = (pz * factor) * inv_pixel_size + v_mid;

        // Sample projection with hardware bilinear interpolation
        float val = read_imagef(projection, sampler, (float2)(u_proj, v_proj)).x;

        // Apply FDK distance weight: (D / d_source)^2
        float dist_weight = (source_to_isocenter * source_to_isocenter) / (d_source * d_source);

        int volume_idx = z * (dim_x * dim_y) + y * dim_x + x;
        volume[volume_idx] += val * dist_weight;
    }
}

5. Memory and Performance Optimizations

  1. Volume Sub-Volume Chunking: High-resolution reconstructions (e.g., \(512^3\) or \(1024^3\) floats) exceed typical GPU local and global memory allocations. Partition the volume along the Z-axis (slices) and process chunks sequentially or via overlapping host-device transfer queues using clCreateSubBuffer.
  2. Work-Group Sizing: Optimal work-group dimensions for the 3D backprojection kernel are typically \(8 \times 8 \times 4\) or \(16 \times 16 \times 1\) to align with GPU wavefront/warp execution sizes (32 or 64 threads).
  3. Pipelining with OpenCL Command Queues: Instantiate multiple in-order cl_command_queue instances or a single out-of-order queue. Overlap the host-to-device memory copy of projection \(N+1\) with the kernel execution of projection \(N\) using OpenCL events for synchronization.
