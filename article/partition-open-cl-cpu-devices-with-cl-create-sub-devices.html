Partition OpenCL CPU Devices with clCreateSubDevices

This article explains how an OpenCL host application divides a multicore CPU root device into independent sub-devices using the clCreateSubDevices API function. It details the prerequisites for querying device partition capabilities, the supported partitioning schemes—such as equal splits, explicit core counts, and cache-affinity domains—and the exact sequence of API calls required to allocate and release these sub-devices safely.

Understanding Device Partitioning

Device partitioning in OpenCL allows an application to break a single compute device (commonly a multicore CPU) into multiple distinct cl_device_id handles called sub-devices. Each sub-device exposes its own subset of compute units, enabling independent command queues, dedicated context control, cache localization, and reduced thread contention across Non-Uniform Memory Access (NUMA) nodes.

Checking for Partition Support

Before invoking clCreateSubDevices, the application must query the root device using clGetDeviceInfo to verify that partitioning is supported:

  1. CL_DEVICE_PARTITION_MAX_SUB_DEVICES: Returns a cl_uint indicating the maximum number of sub-devices that can be created from this device. If this returns 0, partitioning is not supported.
  2. CL_DEVICE_PARTITION_PROPERTIES: Returns an array of cl_device_partition_property flags detailing which partitioning mechanisms the hardware and driver implement.

Partitioning Schemes

The clCreateSubDevices function accepts a property list defined as an array of cl_device_partition_property, terminated by 0. OpenCL provides three primary strategies for partitioning:

1. Partition Equally (CL_DEVICE_PARTITION_EQUALLY)

Divides the root device into sub-devices that each contain an identical number of compute units.

cl_device_partition_property properties[] = {
    CL_DEVICE_PARTITION_EQUALLY,
    4, // Number of compute units per sub-device
    0  // Terminating zero
};

2. Partition by Counts (CL_DEVICE_PARTITION_BY_COUNTS)

Divides compute units into specific, non-uniform subsets. The list of counts is terminated by CL_DEVICE_PARTITION_BY_COUNTS_LIST_END.

cl_device_partition_property properties[] = {
    CL_DEVICE_PARTITION_BY_COUNTS,
    2, // 2 compute units for the first sub-device
    4, // 4 compute units for the second sub-device
    CL_DEVICE_PARTITION_BY_COUNTS_LIST_END,
    0
};

3. Partition by Affinity Domain (CL_DEVICE_PARTITION_BY_AFFINITY_DOMAIN)

Splits the device according to its physical hardware topology and cache hierarchy. This is the most common approach for CPU devices to maximize memory locality and NUMA performance. Supported affinity flags include:

  • CL_DEVICE_AFFINITY_DOMAIN_NUMA
  • CL_DEVICE_AFFINITY_DOMAIN_L4_CACHE
  • CL_DEVICE_AFFINITY_DOMAIN_L3_CACHE
  • CL_DEVICE_AFFINITY_DOMAIN_L2_CACHE
  • CL_DEVICE_AFFINITY_DOMAIN_L1_CACHE
  • CL_DEVICE_AFFINITY_DOMAIN_NEXT_PARTITIONABLE
cl_device_partition_property properties[] = {
    CL_DEVICE_PARTITION_BY_AFFINITY_DOMAIN,
    CL_DEVICE_AFFINITY_DOMAIN_NUMA,
    0
};

Executing clCreateSubDevices

The creation process requires a two-step query to allocate memory and retrieve the sub-devices:

cl_uint num_sub_devices = 0;

// Step 1: Query the number of resulting sub-devices
cl_int err = clCreateSubDevices(
    root_device,
    properties,
    0,
    NULL,
    &num_sub_devices
);

if (err != CL_SUCCESS || num_sub_devices == 0) {
    // Handle error or lack of partition support
}

// Step 2: Allocate memory and populate the sub-device handles
cl_device_id* sub_devices = (cl_device_id*)malloc(sizeof(cl_device_id) * num_sub_devices);

err = clCreateSubDevices(
    root_device,
    properties,
    num_sub_devices,
    sub_devices,
    NULL
);

Lifecycle and Resource Management

Each generated cl_device_id can be used to initialize distinct contexts or command queues, allowing workloads to be scheduled specifically to assigned CPU cores.

Because sub-devices are reference-counted entities, each sub-device must be explicitly destroyed when no longer needed using clReleaseDevice:

for (cl_uint i = 0; i < num_sub_devices; i++) {
    clReleaseDevice(sub_devices[i]);
}
free(sub_devices);

Releasing the sub-devices ensures that driver resources and parent device locks are cleaned up properly without leaking memory.
